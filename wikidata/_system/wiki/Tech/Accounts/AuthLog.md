# 照合の記録とロック

ログインの照合を記録することと、まちがいが続いたときのロックの決まりです。

## 照合したことは記録します

パスワードで照合したときは、通っても通らなくても `wikidata/<Wiki名>/log/auth.log.db` に
残します。

| 残すもの | |
|---|---|
| `unixtime` | いつ |
| `uid` | 打たれた文字列をそのまま（前後の空白も、登録されていない名前も） |
| `remote` | どこから（接続元のIP。下の断りを参照） |
| `authstate` | 下の表のとおり |

| 値 | 意味 |
|---|---|
| `0` | 通った |
| `1`〜`99` | パスワードが違った。値はその時点の連続失敗回数 |
| `100` | ロックした（下の「ロック（`100`）」） |
| `101` | そのIDが登録されていない |
| `102` | 無視した（止めているあいだ。パスワードも違っていた） |
| `103` | 無視した（止めているあいだ。**パスワードは合っていた**） |

2026-09-06より前の記録は `101`:無視、`102`:未登録 の意味のまま残っています。

- `uid` を整えずに残すのは、何が打たれたかを見るためです（照合は前後の空白を落として
  行うので、記録と照合の値は食い違うことがあります）
- `#login` 経由の照合と `/.passwd` の照合を、同じ数えに載せます（片方だけだと、そちらから
  何回でも試せるため）
- 合言葉（cookie）で通ったぶんは残しません（ページを開くたびに起きるため）
- 連続失敗回数は別に数えを持たず、この記録から数えます（`fail_count`）
- 未登録のID（`101`）は連続失敗回数に数えません

#note(type=warn){{
**VPN（Tailscale）経由の接続は、全員が同じIPになります。**

サブネットルータがSNATで送信元アドレスを書き換えるため、元のIPはこのホストに届く前に
失われ、`X-Forwarded-For` も付きません（2026-09-07の調査。Wiki設計者の判断で**対応は
見送り**）。[アクセスログ](/Tech/Reference)も同じです。誰かを追うときは `uid` を見てください。

直すなら経路側です（SNATを切るか、このホストを tailnet に入れる。`tailscale serve` なら
`Tailscale-User-Login` が取れます）。後者では `X-Forwarded-For` が付くようになりますが、
いまの実装（`request.remote_addr`）はそれを無条件に信用するので、信用する手前のアドレスから
のみ採用する判定が要ります。
}}

## 5回まちがえたら、しばらく無視します

5回まちがえたIDは、最後の失敗から10分のあいだ、パスワードが合っていても通しません。

| | |
|---|---|
| 止まる回数 | 5回ごと（`authlog.IGNORE_AFTER`） |
| 止まる長さ | 最後の失敗から10分（`authlog.IGNORE_SECONDS`） |
| 判断に使う数 | 直近20分（無視時間の倍。`authlog.FORGET_SECONDS`）の失敗だけ |
| ロックまで | 3ターン＝15回（`authlog.LOCK_TURNS` / `LOCK_AFTER`） |
| 記録 | `102`（パスワードも違った）／`103`（パスワードは合っていた） |

    5回まちがえた            → そこから10分は止まる（1ターン目）
    10分たった                → また5回まで試せる（6回目〜9回目は通す）
    10回目                   → また10分止まる（2ターン目）
    15回目                   → ロック（3ターン目の終わり）
    20分だれも失敗しなかった → 判断の数は0から。また5回まで試せる

**この仕組みがある前提で、パスワードの強度は4桁の暗証番号程度でよい**としています
（Wiki設計者の指示、2026-09-06）。

- 止めているあいだの断りの文言・待ち時間・転送先は、ふつうにまちがえたときと同じです
  （分けると「そのIDは実在して、いま狙われている」まで外に伝わるため）
- パスワードが合っていたかどうかは記録（`102`/`103`）にだけ残します
- `103` は重い印です（止められた本人か、当てられたか。どちらでもパスワードを変えたほうがよい）
- 止めているあいだの試みは数を進めません（進めると、いつまでも明けないため）

## ロックが近いことの断り

| 残り | 出る文言 |
|---|---|
| 5回以上（＝止めに入る回まで） | 出しません |
| 4〜2回 | ロックまで残りn回（`authlog.WARN_LEFT` から） |
| 1回 | 次回失敗したらロックします |

**止めているあいだも、止めに入る回も出しません**（Wiki設計者の指示、2026-09-07）。
止めているあいだは数が動かないので減らない数が並び、止める回だけ出すと、次に消えることで
「いま止められている」と読めてしまうためです。最後の1回を言葉にするのは、「残り1回」だと
いま失敗したら掛かるのか、次に失敗したら掛かるのかが分からないためです。

    1〜5回目     出さない（5回目のあと、10分止まる）
    止めている   出さない
    明けて6〜10回目 出さない（10回目のあと、10分止まる）
    明けて11回目 ロックまで残り4回
    12回目       ロックまで残り3回
    13回目       ロックまで残り2回
    14回目       次回失敗したらロックします
    15回目       ロック

## ロックまでの数えは、間を空けても戻りません

無視の判断は直近20分で数え直しますが、**ロックまでの数えは通算で、戻るのは通ったとき
だけ**です（Wiki設計者の指示、2026-09-06）。記録の `authstate` も伸びたままなので、
記録を見れば「明けてはまた止まって」を何回繰り返しているかが分かります。

ただし、数え直しのときに残りが1回だと、久しぶりに1回まちがえただけでロックになるので、
そこだけ残り2回まで戻します（Wiki設計者の指示、2026-09-07）。間を空けても、そのたびに
2回までしか買えません。

## ロック（`100`）

15回まちがえたら（3ターン目の終わり）、**`pw` を `LOCKED` に書き換えます**。
`hash_password()` は必ず40文字の16進を返すので、どんなパスワードを送っても通らなくなります。
「ロック中」の欄を別に持たないので、古いDBでもそのまま動きます。

| | |
|---|---|
| 掛かる | 15回目の失敗で自動的に（記録は `100`） |
| 解除 | `/.admin/accounts` でパスワードを付け直す（管理者だけ） |
| `/.passwd` から | 解除できません（`LOCKED` と一致する入力は作れないため） |
| 一覧の見た目 | その行に 🔒 が付き、`pw` の欄が `LOCKED` になります |

ロックだけは、そうと分かる文言（「このアカウントはロックされています。管理者に解除を
頼んでください。」）を出します。黙っていると壊れているとしか見えず、解除を頼めないためです
（IDが実在することは伝わりますが、「残りn回」を出す時点で同じです）。

#note(type=warn){{
**`admin` も止まります**（例外にすると、そこだけ何回でも試せるため）。管理者が自分を
締め出したら、`./wiki.py resetpw` で入れ直します（[下の手順](/Tech/Accounts/AccountList#管理者が入れなくなったとき)。
ロックもこれで解けます）。ログイン中の管理者は、そのあいだ `/.admin/accounts` で解除できます。
}}
