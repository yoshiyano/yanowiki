# 書き込まれる手順

| 契機 | 処理 |
|---|---|
| 編集画面の保存 | `pagesave.save_page()` で拾い直して上書き（[保存](#保存save_page)） |
| バックアップからの復元 | 同上（`merge=False`。戻した事実を必ず1本残す） |
| 名前の変更に伴うリンクの直し | 同上（`merge=False`。[リンクを直す](#リンクを直す)） |
| 直接編集の取り込み | 同上（`write=False`。[直接編集の取り込み](#直接編集の取り込み)） |
| 削除（`pagesave.remove_page()`） | ページの行と、そこから出ていたリンクの行を消す |
| ページ⇄フォルダ（`pagemove.move_page_records()`） | `pagedb.rename_page()` で行と `source` を付け替えるだけで、拾い直さない |

ページ⇄フォルダで拾い直さないのは、`X` ⇄ `X/index` ではページパスが変わらず、相対リンクの
起点も変わらないためです。別フォルダへ移す改名は拾い直しが要るので、`pagerename` は
`pagesave.save_page()` を通ります。

## 保存（save_page）

本文が変わったときは、どこから変えても次の3つを行います。

    バックアップ    公開されていた内容 → 新しい内容 の差分を記録する
    平文ファイル    新しい内容を書き出す（write=False のときは省く）
    DB              本文を入れ直し（record_page）、続けてタイトル・
                    目次・リンクを取り出す（links.update_page_info）

3つは揃っていないと意味がなく、差分は書き換える前に取ります。差分の基準は、平文ではなく
DB（システムが最後に知っている内容）です。平文を直接編集した状態で保存すると、その分も
まとめて1本の差分になります。

## リネーム（rename_page）

実体パスが変わると、紐づくものをまとめて動かし、DBの行も付け替えます
（`pagedb.rename_page`）。`created`・`updated` は引き継ぎ、そのページから出るリンクの行も
`source` を付け替えるだけです。

### リンクを直す

動いたページを指していたページは、`owner` の索引から引きます（`pagedb.backlinks_of`）。
その本文のリンク先を `pagelinks.rewrite_links` で書き換えます。

判断にはDBのキャッシュ（`pagedb.link_rows_of`。書かれたままの文字列 → 解決した先）を使い、
位置は毎回 `link_spans` で見つけます。DBに無い文字列は、その場で `resolve_link` に通します
（`wiki_dir` を渡していれば）。絶対・相対の選びかたなどは
[リファレンス](/Tech/Reference/Rename)にあります。

リンクの直しは、編集画面からの保存と同じ扱いです（差分がバックアップに残り、DBも入れ直す）。
他人のページが書き換わるので、あとからたどれるようにするためです。

## 直接編集の取り込み

編集画面を通さずに書き換えられたページを見つけて、編集画面から保存したのと同じ後始末を
行います（`_sys/wikilib/pagesync.py`）。

取り込んだページは、その場で1回描きます（`pagesync.review_page`）。プラグインが描画の中で
書き出す記録（[ページごとの権限](/Tech/PagePermissions)）があり、ファイルを置いただけの
ページは誰かが開くまで描かれないためです。描いて本文が変わったら、変わらなくなるまで
描き直します（上限 `pagesync.MAX_REVIEW`、5回）。落ち着かなかったページは結果に出ます。

> **ファイルで直したら `./wiki.py updatepage` を実行してください。** 自動の取り込みは
> 取りこぼしを防ぐためのものです。
>
> ```bash
> ./wiki.py updatepage =_system   # wikidata/_system/ のページを直したとき
> ```

| いつ | 何をするか |
|---|---|
| 起動時 | 起動直後に1回（全Wiki） |
| 1時間ごと | バックグラウンドのスレッドで（全Wiki） |
| ページを開いたとき | 平文はあるがDBに無い場合（[ファイルがあれば取り込む](#ファイルがあれば取り込む)） |
| `./wiki.py updatepage` | 手で動かす。1つのWikiが対象 |

`updatepage` の対象は1つのWikiだけです。`=Wiki名` を付ければそのWiki、`wikidata/<Wiki名>/` の
中で実行すればそのWiki、それ以外は既定のWikiです。

```bash
./wiki.py updatepage                     # 対象のWikiの全ページ（消えたページも後始末）
./wiki.py updatepage Tech/EditGuide      # そのWikiの1ページだけ
./wiki.py updatepage =sandbox            # Wikiを指定して全ページ
./wiki.py updatepage =sandbox/Scratch    # Wikiを指定して1ページだけ
./wiki.py updatepage --force             # 食い違いを見ず、全ページを読み直して入れ直す
```

`--force` は実在する全ページを読み直し、目次・リンクまで取り出し直します。`created` は
引き継ぎます。

### 食い違いの見つけかたは2段階

`pagedb.stale_pages()` がページごとに見ます（全体の「ここまで走査した」時刻は持たない）。

    1段階目  大きさが違えば、中身も違う（読まずに確定）
             大きさが同じで更新時刻だけ新しければ、2段階目へ
    2段階目  本文を読んでCRC32を取り、DBの値とくらべる

`git reset --hard`・コピー・`touch` のように、更新時刻だけが変わることがよくあるためです。
中身が同じならDB側の更新時刻を合わせ、次からは読み直しません。CRC32は速さで選んでいます
（約4.0GB/秒。sha256の2.4倍、md5の7倍）。

DBへはページごとに、本文・目次・リンクをまとめて書きます。

### ファイルがあれば取り込む

平文があるのにDBに行が無いページは、開かれた時点で取り込みます（`pagesync.adopt_page`。
`pagedb.published_ref` から呼ばれる）。`git pull` やエディタで置いたページが、`updatepage` を
待たずに読めます。中身は `updatepage` の「追加」と同じ `sync_page` です。初回登録日時は、
バックアップが残っていればそのいちばん古い日時を使います。

DBに行があって内容だけが違うページは、ここでは扱いません（起動時・1時間ごと・`updatepage` に
任せる）。置いただけでまだ開いていないページも、一覧・検索・逆リンクへの反映はそれらを待ちます。

### 空のフォルダを片付ける

Wiki全体を取り込むとき（起動時・1時間ごと・`updatepage`）は、最後に中身の無いフォルダを
`wiki/` から消します（`pagesync.prune_empty_folders`）。1ページだけの取り込みでは行いません。

消すのは、下位も含めてファイルが1つも無いフォルダです。次のものは残します。

| 残すもの | なぜ |
|---|---|
| その下に書きかけがある | ページを作りかけている |
| 入口（`X/index`）に添付がある | ページより先に添付だけ置いてある |
| 作られてから10分に満たない | 保存の途中かもしれない（`save_page` は階層を作ってからファイルを書く） |

添付の置き場（`attach/`）の空のフォルダも、同じときに消します（`pagesync.prune_empty_attach_folders`）。
残すのは作られてから10分に満たないものだけです。添付を置く処理は、置く前にフォルダを作り直すためです。

消したフォルダは起動ログに「中身の無いフォルダを片付けました」と出ます。ページの一覧は
中身の無いフォルダを表示から外すだけで、消すのはこの取り込みだけです。
