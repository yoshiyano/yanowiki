# 同じ名前の .txt と .md を整理する仕組み

使いかたは [同じ名前の .txt と .md があるとき](/UsageGuide/Edit/Duplicate) にあります。このページは仕組みの説明です。

同じページ名に `.txt` と `.md` が両方あると、読まれるのは `.txt`（`paths.PAGE_EXTS` の順）だけで、
`.md` は画面からは気づけません。タイトル右端の info（テーマの変数 `page_info`。`wikilib.pagenotice`）に警告を出し、
押すと整理の画面 `/.solveDupPage/<ページ名>`（`wikilib.solvedup`）が開きます。そこで2つのファイルを見比べ、
どちらかを採用すると、選ばなかったほうが名前に `_bak` を付けたページとして残ります。
同じ名前のファイルとフォルダ（`X.md` と `X/`）も、同じ画面で整理します（下の「同じ名前のファイルとフォルダ」）。

## 流れ

| 段 | 何が |
|---|---|
| 知らせ | ページを描くとき（`themes.render_with_theme`）、同じページ名の実ファイルが2つあれば、info に `<a>`（⚠）を渡す。閲覧できる人全員に出す。つなぐ先は、そのWikiの `/.solveDupPage/<ページ名>` |
| 画面（GET） | 先頭に状況の説明と説明ページへのリンク。続けて2つのプレビュー（左右。縦幅は 720px まで）、添付とアクセス制限の状態、採用のボタン |
| 整理（POST） | `solvedup.solve`。次の手順で行い、どこで失敗しても整理の前へ戻す |

画面を開いてから押すまでにファイルが書き換えられていないかは、フォームが持つ本文のハッシュ（`hash.txt`・`hash.md`）と、整理の直前の本文を照合して確かめる。

## なぜ既存の名前の変更（`pagerename`）を使わないか

`rename_page` はページ名を単位にするので、同じ名前の2つのうち `.txt` 側を動かし、**添付・履歴・書きかけ・DBの行・
アクセス制限の記録まで新しい名前へ付け替える**。ここでは片方のファイルだけを `_bak` にして、残すほうは今の記録のままにしたい。
そこで専用に行う。

## 整理の手順

1. 操作した人が `_bak` のページを編集できるかを確かめる（できなければ断る。いま当たっている指定のまま見る）
2. 添付を、ファイルごとの移動先に従って `_bak` へ写す・移す
3. 退けるほうのファイルを `_bak` の名前へ動かす（`os.replace`）
4. DBを合わせる。採用したほうは `sync_page`（差分が履歴に残る）、`_bak` は `adopt_page`（新しいページとして始まる）

3までのどこかで失敗したら、移した添付を戻し、写した添付を消す（戻せなかったものがあるときは、唯一の置き場所なので消さない）。
4だけが失敗したときは、整理は済んだものとして扱う。取り込み（1時間ごと・`updatepage`）が同じことをするため。

**アクセス制限の記録（`config/privileges`・`config/privileges.plugin`）は書き換えない。**

## `_bak` の名前

`<名前>_bak`、使えなければ `_bak2`・`_bak3` … と空きを探す（上書きしない）。次のどれかがあれば、その名前は使わない。

- 同じ名前のページのファイル・フォルダ
- 添付の置き場所、書きかけ、履歴
- DBの行
- 手で書いたアクセス制限の完全一致の行

フォルダの入口（`Tech/index`）は、実体パスに `_bak` を付ける（`Tech/index_bak`。ページ名は `Tech/index_bak`）。

## 添付（ファイルごとの移動先）

重複している2つのファイルは、同じ添付の置き場所（`attach/<実体パス>/`）を使っている。整理すると別のページになるので、
画面で**ファイルごとに**移動先を選ぶ。置き場所の直下のファイルだけを扱い、下位ページの添付（下のフォルダ）は動かさない。

フォームのフィールドは、ファイルごとに `dest:<ファイル名>`（値は `both`・`txt`・`md`）。画面の「すべて（一括）」の
ラジオボタン（`dest-all`）は、JSが各ファイルのラジオボタンへコピーするためのもので、サーバーは読まない。
ファイル名は日本語などを含みうるので、`request.forms.decode()` で読む。

「.txt 側」「.md 側」は、そのファイルのページ（フォームの値は `txt`・`md`）。
**採用したファイルのページが元のページ（`A`）、採用しなかったほうが `A_bak`** になるので、どちらを採用するかで
どちらの側がどちらのページになるかが決まる（`solvedup.attach_modes`）。

| 移動先 | 採用したページが | 動き |
|---|---|---|
| 両方 | （どちらでも） | 元のページに残したまま、`_bak` へ写す |
| .txt 側・.md 側 | その側のファイルを採用 | 元のページだけに残す（`_bak` へは動かさない） |
| .txt 側・.md 側 | その側のファイルを採用しない | `_bak` へ移す（元のページには残さない。空になった置き場所は消す） |

画像ファイル（`paths.IMAGE_EXTS`）の名前のマスには、`data-img`（`/.attach/<実体パス>/<ファイル名>`）を付け、
マウスを重ねるとJSが1つの浮かぶ要素でプレビューを出す。画像以外には付けない。

## アクセス制限は案内だけ

`_bak` は新しい名前なので、元のページだけに効いていた制限が当たらず、**整理した直後から、制限が緩い（または無い）状態になりうる**。
完全一致（`A`）だけでなく、後方一致（`*Secret` は `MySecret` に当たるが `MySecret_bak` には当たらない）でも起きる。

この画面は**書き換えず**、次を出す（`solvedup.access_report`）。

- 元のページに当たっている R・W の指定と、`_bak` に当たる指定（`auth.page_privilege_rules`）を並べた表
- 元のページに指定があるのに、`_bak` に当たる許可者が違う（指定が無い）種類があれば、赤い枠で知らせる。採用のボタンの確認にも出す。結果の画面にも、同じ警告を出す
- 「アクセス制限」の文字から、アクセス制限の画面（`/.admin/privileges`）へのリンク。**別ウィンドウで開く**ので、この画面を残したまま設定できる。管理は開いた先の画面に任せる。開きかたは `onclick` の `window.open(this.href, '_blank', 'popup,noopener,width=1100,height=800')` で、`return false` でリンクそのものの移動は止める。**`noopener` は features に入れる**（`<a rel="noopener">` は `window.open` には効かない）。開いた先から `window.opener` でこの画面を操作されない。Ctrl+クリック・中クリックは、`href` のとおり通常のリンクとして開く
- 本文のプラグイン（`#readauth`・`#writeauth`）によるアクセス制限は、**どちらのファイルの本文に何が設定されているか**を表で示す。許可者は出さず、`_bak` へも写さない。`.txt` と `.md` の本文は別なので、採用するほうで整理後の制限が変わる。見つけかたは `updatepageauth` と同じで、本文の字面ではなく、プレビューと同じ描画（`partial=True`）をして `context.used_plugins` に `readauth`・`writeauth` があるかを見る（囲みコードの中などを読み違えない。描くときにプラグインは記録を書かない）。描けなかったファイルは「調べられませんでした」と出す。空の呼び出し（`#readauth()`）も「呼ばれた」に数える

アクセス制限の画面は、ページ名の事前入力を受けないので、リンクは画面そのものを指す。

## 同じ名前のファイルとフォルダ

`X.md` とフォルダ `X/` が並ぶと、`resolve_page_ref` はフォルダの入口 `X/index` を読むので、`X.md` は読まれない
（入口が無ければ、ページ `X` は無いことになる）。これも重複として扱い、`X.拡張子` と `X/index.拡張子` の間で整理する
（`solvedup.solve_folder`）。見つけるのは `paths.shadowed_twin`（入口の実体パスから、同じ名前のファイルを探す）。

| 採用 | 動き |
|---|---|
| 入口 `X/index` | `X` → `X_bak` |
| ファイル `X` | `X/index` → `X_bak`、続けて `X` → `X/index`（入口を先に空ける） |
| 入口が無い | `X` → `X/index` だけ |

- **`.txt` と `.md` の重複と違い、2つのファイルは実体パスが別**なので、添付・履歴・書きかけ・DBの行ももともと別々。
  どれもファイルに付いたまま動かす（`move_backups`・`move_draft`・`pagedb.rename_page`）。添付の移動先は選ばせない
- 添付は**置き場所の直下のファイルだけ**を動かす。`attach/X/` の下には、`X/index` や下位ページの添付のフォルダが
  並んでいるため（`pagemove.move_attach_dir` は置き場所ごと動かすので使わない）
- ファイルと添付を全部動かしてから記録を付け替える。ファイルの移動のどこかで失敗したら、逆の順に戻す
- 動かしたページは、DBに行があれば `sync_page`、無ければ（手で置いて未取り込み）`adopt_page` で揃える
- フォームのハッシュは `hashfile`・`hashfolder`（同じ拡張子どうしもありうるので、拡張子では分けない）

### 1段ずつ整理する

重複が重なっているときは `pagenotice.duplicate_stage` の順に1段ずつ片付ける。info の ⚠ も、整理の画面も、
その時点の段だけを扱う。結果の画面は、まだ残っていれば「続けて整理する」を出す。

1. 入口の `.txt` と `.md`（`X/index`）
2. 隠れたファイルの `.txt` と `.md`（`X`）。ページ名 `X` で開くと入口が開くので、ほかに整理する道が無い。
   `.txt` と `.md` の整理（`solve`）をそのまま使うが、**`X` は取り込まない**（`sync_page` はページ名で読むので、
   入口を読んでしまう）。3 の整理で取り込む
3. ファイル `X` と入口 `X/index`

フォームは開いたときの段（`stage`。`ext:<実体パス>`・`folder:<実体パス>`）を持ち、押すまでに段が替わっていれば断る。

入口が無いときのページ `X` は「このページはまだありません」の画面（`views.render_no_page`）になる。そこでも info に ⚠ を渡す。

## 権限

- 閲覧（R）が無ければ、閲覧できないページと同じ画面（403）
- 編集（W）が無ければ、状況の説明だけを出す（403）。**取り込み前のほうの中身（プレビュー）も、選ぶボタンも出さない**。読むだけの人に、公開前の内容が見えてしまうため
- 許可者（ログインID・グループ名）の一覧は、管理者と助手にだけ出す。`/.admin/privileges` が管理者向けに持つ情報なので、編集の権限だけでは見せない。それ以外の人には指定の件数だけを出す
- 助手の操作は `page.dupsolve` で記録する（[助手の操作の記録](/Tech/StaffLog)）。記録だけで、戻す操作は無い

このうち、アクセス制限を書き換えないこと（案内とリンクだけ）は、設計者の指示。**整理した直後の `_bak` は、元のページの制限が付かないまま
作られる**（上の「アクセス制限は案内だけ」）。設計者がそのうえで選んだ方針で、画面は、その状態に気づけるよう警告とリンクを出す。
