# ファイル一覧の仕組み（`/.files/`）

ページをエクスプローラーの形で見せ、名前の変更・移動・コピー・削除・新規作成などを行う画面です。
使いかたは [ファイル一覧](/FilesGuide) にあります。ここは構成と、各操作がどの処理を呼ぶかの
まとめです。細かい決まりと経緯は `_sys/wikilib/filesui.py` の冒頭に書いてあり、そちらが正本です。

## 構成

画面と API は、同梱の **webFileDir**（`_sys/webfiledir`、1.0.1。由来と更新は `WIKISYSTEM.txt`）を
そのまま使います。wikiSystem は webFileDir の「プロバイダ」（一覧を返し、操作を受ける側）を
書いて、Wikiのページの木を見せています。

```
/=<Wiki名>/.files/…   wiki.py の dispatch
  -> filesui.serve_files     画面（/.files/）だけは wikiSystem が返す（題名を Wikiの名前にする）
  -> Wikiごとの webFileDir のアプリ（初めて使うときに作って持つ）
  -> WikiPagesProvider       一覧・操作を wikilib の関数へつなぐ
```

- webFileDir には手を入れず、`webfiledir` という名前で読み込みます（最上位のパッケージ名
  `server` が `_sys` の中でぶつからないように）。0.2 系を読み込んだときは 503 を返します
- 開くのにログインは要りません。見えるのは読む権限のあるページだけで、操作ごとに権限を確かめます
- 時間のかかる操作は webFileDir が裏のスレッド（ジョブ）で行います。そこでは cookie が読めないので、
  要求の中で閲覧者を判定して固定します（`auth.fix_viewer`）
- ほかの人の変更を自動で映す仕組み（webFileDir の自動更新）は使っていません（`live_updates=False`）

## 見せかた

| webFileDir | Wiki | 備考 |
|---|---|---|
| フォルダ | 中にページを持つフォルダ | 入口（`X/index`）があれば、そのタイトルなどをフォルダの行に重ねる |
| ファイル | ページ | 名前に拡張子を付けない（`ext=""`）。書きかたは「書きかた」の列で見せる |
| — | トップページ | 直下の入口だけは `(TopPage)` というファイルとして出す |
| — | 添付ファイル | 項目にせず、「添付」の列に数だけ出す |

一覧は必ず `pagelist.scandir` を通し、読む権限の無いページと、見えるページの無いフォルダを出しません
（[ページの一覧を作る](/Tech/PageList)）。更新日時・サイズは DB（pagedb）の値です
（Wiki設計者の「DBで完結するようにすべきです」、2026-09-29）。

## 操作と、呼ぶ処理

| 操作 | webFileDir のコマンド | 中身 |
|---|---|---|
| ページを参照 | 独自 `page`・`dir-page` | ページのURLを新しいタブで開く。フォルダは入口のページ |
| ページの編集 | 独自 `edit` | ページのURLへ `cmd=edit` を POST で送る（新しいタブ） |
| 新しいタブで開く | 独自 `new-tab` | 既定の `tab` は Shift を使うので止め、作り直した |
| 名前の変更・移動 | 既定 `rename`・貼り付け・ドロップ | `pagerename.rename_page`。リンクも直る（[リネームの仕組み](/Tech/RenamePage)） |
| コピー | 既定 コピー → 貼り付け | `pagecopy.copy_pages`。アクセス制限・添付・リンクも写す |
| 削除 | 既定 `delete` | `editor.delete_page`（本文を空にして保存したときと同じ。添付は `/trashbox` へ移す）。フォルダは、ページの無い下位フォルダの添付も移す。添付があれば、削除の前に［はい］［いいえ］で尋ねる（`before_delete`。webFileDir 1.2.0 から） |
| 新しいフォルダ・ページ | 既定 `mkdir`・`touch` | `pagesave.save_page`。フォルダは入口 `index` を `#ls()` の本文で作る |
| 見出し連番 | 独自 `page-numbering` | 名前の変更を順に行う（webFileDir の見本 `numbering` と同じ宣言） |
| フォルダ化 | 独自 `page-to-folder` | `pagemove.convert_page_to_folder`（`X` → `X/index`。URLは変わらない） |
| 中断した操作を続ける | 独自 `resume` | `pagerename.resume_operation` |

ごみ箱はありません（プロバイダの capabilities に無い操作は、webFileDir がメニューにも出さず、
直接呼んでも断ります）。

## 権限

webFileDir は項目の権限（`Entry.auth`。動かす・読む・書く・実行）を見て、ボタンやメニューを灰色に
します。Wikiの権限は次のように当てはめます（クロコの案を設計者が承認、2026-09-29）。

| ビット | 値 |
|---|---|
| 動かす | 動くページすべてに編集の権限があれば 1（`pagerename.unwritable_pages` が空）。トップページは 0 |
| 読む・実行 | 1（見えないページは一覧に出さないため） |
| 書く | 1（フォルダの時点では中に作れるかが決まらない。作るときに確かめる） |

webFileDir の API は項目の権限を見て断らないので、**操作ごとにプロバイダが改めて確かめます。**

## 止めて続きから

名前の変更・移動は作業の手順のファイル（`pageinfo/operations/`）に沿って行い、進み具合と［中止］を
webFileDir のジョブに出します。止まった操作は、何も無いところの右クリック「中断した操作を続ける」か、
管理の画面の `/.admin/operations` から続けます（[リネームの仕組み](/Tech/RenamePage#止めて続きから再開する)）。

## 設計者の指示と、クロコの実装例

設計者の指示（`filesui.py` の冒頭に原文と日付があります）:

- 一覧の列の順（名前・タイトル・更新日時・サイズ・添付・書きかた）と、トップページを `(TopPage)` と出すこと
- 「開く」ではなく「ページを参照」と呼ぶこと。フォルダの入口は Shift かメニューで開くこと
- 「ページの編集」をメニューに置くこと（POST で開く案を選んだ）
- 新しいフォルダは入口 `index` を、Wikiの既定の書きかたで、本文 `#ls()` で作ること
- まとめて動かすときは1件ずつ行い、権限の無いものだけを失敗にすること
- 削除・コピー（複製ではなく）・見出し連番・フォルダ化を足すこと

クロコの実装例（設計者は未確認）として残っているもの:

- 新しいページの書きかた・本文（`（まだ内容がありません）`）と、既定のファイル名を「新しいページ」に置き換えること
- フォルダの削除は、中のすべてに編集の権限があるときだけ、まとめて行うこと
- コピーでトップページを写さないこと
- 中断した操作は、動くページすべてを編集できる人なら、始めた本人でなくても続けられること
- フォルダ化の表示名・複数選択・本文に `#ls()` を足さないこと
