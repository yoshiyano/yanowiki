# アカウントの一覧とパスワードの変更

管理者がアカウントを直す画面と、パスワードを変える・ハッシュ値を作る道具です。

## アカウントの一覧（`/.admin/accounts`）

#img(アカウントの一覧（パスワード欄は伏せ字にしてあります）>accounts.png)

管理者（番号1）としてログインしている人だけが開けます（ほかは断りの画面と403。POSTも同じ）。

- 判断は[ログインのcookie](/Tech/Accounts/Login)（`wikiuser` と `wikiauth` の組）で行います
- 管理者かどうかは `uid` ではなく `uidnum` で見ます（`userdb.is_admin`。名前はこの画面から
  書き換えられるので、`uid == "admin"` だと名前を変えるだけで管理者になれてしまう）
- ここに届く人は他人のパスワードを書き換えられ、誰にでもなりすませます
- 断る文言は、未ログインでも管理者でなくても同じです（IDの有無を確かめる手がかりにしない）

#note(type=warn){{
**最初のパスワードを既定の `adminpw` のままにすると、絞った意味がありません。**
`/.newwiki` と `./wiki.py initusers` は、パスワードを必ず決めてもらいます
（Wiki設計者の指示、2026-09-08）。それより前に作ったWikiは、下の手順で入れ直してください。
}}

### 管理者が入れなくなったとき

パスワードが分からなくなったときや、管理者自身がロックされたときは、画面からは
戻れません。サーバーで次を実行します（ロックもこれで解けます）。

```sh
./wiki.py resetpw =<Wiki名>
```

Wiki名を省略すると一覧から選べます（取り違えを防ぐため、いまいる場所や既定のWikiで
黙って進めません）。続けて、そのWikiのトップページのフッターを丸ごと貼り付けます。
`Last-modified` と `DiskUsage` の両方が合えば先へ進み、合わなければその場でやり直せます。

```
[sandbox] のトップページを開き、フッターを丸ごと貼り付けてください。
> Convert-time: 17.1ms Last-modified: 2026-09-07 09:52 DiskUsage: Page/Attached 88KB/4.7MB

[sandbox] 確認できました。
```

これはなりすまし対策ではなく、別のWikiを指してしまうのを防ぐものです。`--no-check` で
省けます（端末が無いときは必須）。パスワードは実行時に2回聞きます（`--password` でも渡せます）。

記録を直接書き換える手もあります（ハッシュ値は [`/.pwhash`](#ハッシュ値を作るpwhash) で作れます）。

```sh
sqlite3 wikidata/<Wiki名>/config/users.db \
  "UPDATE passwd SET pw = '<ハッシュ値>' WHERE uidnum = 1;"
```

登録されているアカウントを表で出し、その場で直せます。更新・削除のボタンは、行ごと
ではなく表の上にあります。

- **更新** … 表の中でID・名前・パスワードを書き換え、「変更を更新」を押します。値を変えた
  行だけを、1ユーザーずつ順番にAPIへ送ります
  - パスワードの欄には保存されているハッシュ値が出ています。右の「パスワードとして入力」に
    チェックを入れると、書いた文字を生のパスワードとしてハッシュにして登録します（変更後の
    IDで計算）。チェックが無いときはハッシュ値として受け付け、40桁の16進以外は断ります
  - 欄を空にして更新すると、そのアカウントをロックします（確認のダイアログが出ます）
  - IDを変えるときは、パスワードも付け直します（ハッシュにIDが混ざるため）
- **削除** … 番号の右のチェックボックスで選び、「選んだ行を削除」を押します（1つも選んで
  いないと押せません。確認のダイアログが出ます）。`admin`（番号1）は選べません
- **追加** … 下の欄から、新しいIDだけを足します（フォーム送信）。パスワードかハッシュ値の
  どちらかを入れます（両方ならパスワードが優先）

### 更新・削除は、1ユーザーずつAPIへ送っています

`accounts.js` が、対象のユーザーを1人ずつ順番に `/.admin/accounts/api` へPOSTします。
途中で1件だけ失敗したときに、どこまで進んだかを追えるようにするためです。

    POST /.admin/accounts/api
    {"cmd": "update", "uidnum": 2, "uid": "…", "name": "…", "pw": "…"}
    {"cmd": "delete", "uidnum": 2}

    → {"ok": true/false, "message": "…"}

ログイン状態は画面と同じcookieで判断します（`fetch` に `credentials: "same-origin"`）。
断るときもJSONで返します。

誰が・どのアカウントに・何をしたかを、成功・失敗のどちらも
`wikidata/<Wiki名>/log/admin.log.db` に積み上げます（`wikilib.adminlog`）。

| 残すもの | |
|---|---|
| `unixtime` | いつ |
| `actor_uid` | 誰が（その呼び出しでログイン中だったuid） |
| `cmd` | 何を（`update` / `delete`） |
| `target_uidnum` / `target_uid` | どのアカウントに（操作前の値） |
| `ok` / `message` | 成功したか・userdb側の文言 |

照合の結果を残す[認証の履歴](/Tech/Accounts/AuthLog#照合したことは記録します)（`auth.log.db`）とは別の記録です。
この記録を眺める画面はまだありません。

## パスワードを変える（`/.passwd`）

ID・いまのパスワード・新しいパスワード（2回）を入れると、パスワードを差し替えます。
いまのパスワードを知らないと変えられません（他人のパスワードは管理者が `/.admin/accounts` で
差し替えます）。違っていたときは1秒おいてから断り、失敗の数え・無視・ロックもログインと
同じです。

## ハッシュ値を作る（`/.pwhash`）

IDとパスワード（2回）を入れて、一致したときだけハッシュ値を出します。出てくる値は
このWikiのこのIDのもので、別のWikiや別のIDには使えません（塩とIDが混ざるため）。
入れた値も作った値も記録しません。
