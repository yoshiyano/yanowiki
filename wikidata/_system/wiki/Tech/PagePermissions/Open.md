# まだ埋まっていないところ

決まっていないことと、これから足すものです。

## まだ埋まっていないところ

### グループのメンバーは、他人をそのグループに入れられる

`auth.can_edit_group` により、`g:foo` のメンバーは他人を `g:foo` に追加できます（「助手が助手を
増やせる」ための決まり）。`g:foo` に閲覧権限を与えると、与えた先の人数は後から増えます。

未知のグループ名を書けない決まりで、「まだ無いグループ名に権限を書いておき、第三者がその名前で
作る」筋は塞がっています。**権限に使うグループの中身をメンバー自身が動かせてよいか**は、
まだ決めていません（そのままでよいなら、そう決めれば仕様になります）。

### 編集者の記録

「書き換え者は `system`」「ファイル直接操作は `admin`」「疑わしいユーザの作業一覧」の記録先は
まだありません。バックアップの表 `backup(subpath, stamp, diff, size)` にも、ページの表にも
「誰が」の欄がありません（`adminlog` は `/.admin/accounts` の操作だけ、`authlog` は認証の照合だけ）。

案: **`backup` 表に `editor` 列を足し**、`pagesave.save_page` に `editor` 引数を足す。
版ごとの「誰が」が履歴に並び、作業一覧は `WHERE editor = ?` で引けます。既存の行は NULL になります。

    編集画面・セクション保存   いまログインしている人の uid
    #comment / #vote など      system
    取り込み（updatepage・自動の取り込み pagesync.start_watcher）   admin

自動の取り込みも「admin」として記録されるので、ファイルを手で触った人が誰かまでは分かりません。

- `wikilib.markers` の説明に「wikiSystemにはログイン・アカウントの仕組みが無く」とある。
  いまは事実と違う（状態を localStorage に置くこと自体は変えなくてよい）

管理者は `uidnum = 1` の1人のままです（設計者の判断、2026-09-21。代わりに助手グループで
