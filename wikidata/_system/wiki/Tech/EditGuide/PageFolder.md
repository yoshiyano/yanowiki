# ページとフォルダ・削除

下位ページを作ったときのページとフォルダの行き来と、ページの削除です。

## ページとフォルダの行き来

`Tech/ChangeLog` というページがあるところに `Tech/ChangeLog/2026-08-11` を作りたい——
という場面では、同じ名前のページとフォルダは共存できません。
そこで**必要に応じて自動で作り替えます**（`_sys/wikilib/pagemove.py`）。

### 展開（ページ → フォルダ）

下位ページを保存するとき、途中の階層に同じ名前のページがあれば、
そのページを入口ページへ移してフォルダにします。

```
Tech/ChangeLog.md          →  Tech/ChangeLog/index.md
                               Tech/ChangeLog/2026-08-11.md（新しく作るページ）
```

**URLは `/Tech/ChangeLog` のまま**です。`/Tech` が `Tech/index` を指すのと同じ約束なので、
リンクも添付の参照も切れません。

### 集約（フォルダ → ページ）

下位ページを消した結果、中身が入口ページだけになったフォルダは、ふつうのページに戻します。

```
Tech/ChangeLog/index.md    →  Tech/ChangeLog.md
（フォルダは削除）
```

展開の逆です。この2つが揃うことで、**下位フォルダの作成と削除を意識せずに行き来できます。**

### 一緒に動かすもの

ページの実体パス（`subpath`）が変わると、それに紐づくものも動かないと参照が切れます。

| 動かすもの | 置き場所 |
|---|---|
| ページ本体 | `wiki/<subpath>.<ext>` |
| 添付ファイル | `attach/<subpath>/` |
| バックアップ | `pageinfo/backup.db` の該当行（ページの実体パスの列を付け替える） |

内容は変わらないので、**バックアップに新しい差分は作りません**（実体パスが変わっただけのため）。

なお、展開と集約では移動元と移動先が親子になります（`attach/X` と `attach/X/index`）。
そのまま移すと「自分の中へ自分を移す」ことになって失敗するので、
展開ではいったん隣の名前へ逃がし、集約では中身を1つずつ親へ持ち上げています。

## ページの削除

**本文を空にして保存すると、そのページを削除します。** ファイルごと消すので、
中身が空のページが残ることはありません。削除専用のボタンは置かず、
「空にする」という操作そのものに意味を持たせています。

判定は `source.strip()` が空かどうかです。空白や改行だけの場合も削除になります。

### 確認は出さない

その代わり、編集画面に「本文を空にして保存すると、このページは削除されます」と
**常に書いてあります**。押した結果が変わる確認ダイアログより、
何が起きるかを先に示しておくほうが確実だという判断です。

### 添付ファイルがあるときは削除しない

そのページに添付ファイルが1つでも残っていれば、削除せずに警告を出します。

ページだけ消すと参照元を失った添付が宙に浮き、かといって一緒に消すと
取り返しがつきません。**どちらを選ぶかは持ち主に決めてもらう**ことにして、
先に「添付ファイル」タブで削除するか別のページへ移してもらいます。

### 消える前の内容は残す

削除も保存の一種として、**「全文 → 空」の差分**を `pageinfo/backup.db` に記録します。
差分を逆適用すれば、消える直前の内容がそのまま戻ります。

このときだけは**10分以内の統合を行いません**（`backup_page(..., merge=False)`）。
作ってすぐ消した場合、統合すると「空 → 空」で差し引きゼロになり、
消える直前の内容がどこにも残らなくなってしまうためです。

なお、同じ秒に2回保存すると日時（記録を指す名前）が衝突します。空くまで1秒ずつずらすので、
先に書いた差分が上書きされることはありません。

### あと片付け

- 空になったフォルダを上へたどって片付けます。残しておくと、
  ページ選択ダイアログに中身の無い階層が並んでしまうためです
- `Tech/index` のようなフォルダ自身のページを消しても、**中の他のページは残ります**

まだ無いページを空のまま保存した場合は、何も作らずにページへ戻ります。
