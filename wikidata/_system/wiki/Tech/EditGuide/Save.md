# 保存の仕組み

保存の手順（差分の記録・競合の検出）と、保存先の決めかたです。

## 保存

そのページ自身の通常URLへ `POST`（`cmd=save`）で保存し、成功したら 303 で
ページ本体へ戻ります。

### バックアップ（差分の記録）

保存のたびに「上書き前 → 上書き後」の**unified diff** を
`wikidata/<Wiki名>/pageinfo/backup.db` へ1件ずつ記録します。全文を世代ごとに
複製するのに比べて無駄がなく、**何がどう変わったかがそのまま読めます。**

1件は「どのページか（実体パス）・いつか（`yymmdd_hhmmss`）・差分・大きさ」を
持ちます。日時はその記録を指す名前でもあり、履歴タブが時点を
指定するのに使います。

新規作成も「空の内容からの差分」として記録するので、差分を新しいほうから順に
逆適用していけば最初の版まで復元できます。

#### 置き場所をファイルからDBに移しました（2026-08-31）

以前は1回の保存につき1つの `.diff` ファイル
（`pageinfo/backup/Tech_ChangeLog.260813_214056.diff` のような名前）でした。
同じ日に世代数の上限を撤廃して大きさで区切る形にしたことで、1つのフォルダに
**1万本を超えるファイルが並びうる**ようになったため、DBへ移しました。

- 1ページの履歴を出すだけでフォルダ全体を舐めていたのが、索引1回で済む
- 差分の中央値は2KBほどで、4KBのブロックに1本ずつ置くと実バイトの
  1.8倍ほどをディスク上で占めていた（`_system` は2.7MB→1.9MBになりました）
- ページ名をファイル名に押し込むために `/` を `_` へ退避する仕掛けが
  要らなくなった（実体パスをそのまま列に持てるため）

**移行は自動です。** DBが無いWikiで初めてバックアップに触れたときに、既存の
`.diff` ファイルを一度だけ取り込みます。取り込み元のファイルは消さずに
残してあるので、移行後の履歴を確かめてから片付けられます。

**残す量は世代数ではなく大きさで区切ります**（Wiki設計者の指示、2026-08-31）。
差分の合計が**各Wikiごとに50MB**に達したら掃除します。1回の変更量は
大小さまざまなので、世代数で区切ると「どれだけ残せるか」も「どれだけ場所を
使うか」も見当がつかないためです（それ以前は1ページ20世代まででした）。

掃除の決まりは3つです（Wiki設計者の指示、2026-09-01）。

| 決まり | 理由 |
|---|---|
| **上限の半分（25MB）まで**減らす | ぎりぎりまでしか減らさないと、以後は保存のたびに掃除が走り、そのたびに古い記録が1件ずつ削られていく |
| **記録が20件に満たないページからは消さない** | 上限に触れる原因はたいてい保存の多い一部のページ。めったに更新しないページの数少ない記録を巻き添えにしない |
| **古い保存から順に。候補が尽きたら打ち切る** | 半分まで減らせなくても、履歴を削ってでも必ず収める、とはしない |

消していくうちに20件を割ったページも、そこで対象から外れます
（**どのページにも19件は残ります**）。20件以上のページが1つも無ければ、
上限を超えていても1件も消えません。

消すのはいつも古い側なので、残った差分は新しいほうからそのままたどれます。
「どこまで戻せるか」が縮むだけで、履歴が途中で欠けることはありません。

### 10分以内の保存はまとめる

**直前の差分が10分以内に作られていた場合は、そこまでさかのぼった1本の差分に
まとめ直します**（日時は最後に保存した時刻になります）。
少しずつ手直ししながら何度も保存すると、記録が推敲の途中だらけになってしまうためです。

まとめるときは、**直前の差分を現在の内容に逆適用**して「その差分を取る前の内容」を
復元し、そこから最新の内容への差分を作り直します。まとめた結果として変化が
無くなった場合（元に戻した場合）は、記録そのものを取り下げます。

なお、末尾に改行の無い行には `\ No newline at end of file` の印を付けています。
これが無いと次の行と続いてしまい、差分として読み戻せなくなるためです。

### 競合の検出

編集画面には、開いた時点の内容のハッシュ（`origin`）が埋め込まれています。
保存時に現在のファイルのハッシュと突き合わせ、食い違っていれば**上書きせずに
[統合する画面](/Tech/ConflictMerge)へ送ります**（Wiki設計者の指示、2026-09-01）。

別のタブやセクション編集から同じページを保存した場合に、相手の変更が黙って
消えるのを防ぐためです。

**以前はここで警告を出して編集画面に戻していました。** 入力内容は残るので
書いたものは失われませんが、**もう一度「保存」を押すと相手の変更がまるごと
上書きされます。** 相手の変更を残したければ、画面を見比べて手で写すしか
ありませんでした。統合する画面では、**自分の編集に相手の変更を相違点ごとに
取り込んで**から保存できます。

送り込むときに、入力された本文を**書きかけとして預け直します**（統合画面は
それを「自分の編集」として読みます）。`origin` も一緒に残し、統合した結果を
保存するときまで「何から分かれた変更なのか」を保ちます。

保存できずに編集画面へ戻す場合（本文が届かなかった・削除できなかった等）は、
**画面に出す本文（入力されたもの）と、突き合わせに使う内容（保存されて
いるもの）を別々に持ちます。** 同じ変数に入れると、埋め込むハッシュまで
入力内容のものになり、**押しても押しても断られ続ける**状態から抜け出せなく
なります（実際にそうなっていました）。

| | 画面に出す本文 | 埋め込むハッシュ |
|---|---|---|
| ふつうに開いたとき | 保存されている内容 | 保存されている内容 |
| 削除できなかったとき | **入力された本文**（空） | 保存されている内容 |

削除できなかったとき（添付ファイルが残っている等）は、添付を片付けてから
もう一度押せば、そのまま削除できます。

### セクション編集からの保存

見出し単位の保存（`POST /.section/<ページパス>`）も、ここと同じ後始末を
通ります。宛先の確かめかたと競合の扱いは
[セクション編集](/Tech/SectionEditing#保存のやりとり) にまとめてあります。

## 保存先の決めかた

保存先は、URLのページパスではなく**実際に解決されたファイル**（拡張子抜き）を使います。
この解決は [対象ページの特定](/Tech/Reference/Resolve#対象ページの特定) にある `resolve_page_ref()`
がまとめて行い、編集・保存・プレビュー・添付・バックアップのすべてが同じ答えを使います。

| URL | 保存先 |
|---|---|
| `/UsageGuide` | `wiki/UsageGuide.md` |
| `/Tech` | `wiki/Tech/index.md` |
| `/`（ルート） | `wiki/index.md` |

`/Tech` のようなフォルダ相当のURLは `Tech/index.md` に解決されるため、
ページパスをそのまま使うと `Tech.md` という別のファイルを作ってしまいます。

なお、ブラウザは textarea の改行を CRLF に変換して送るため、保存時に LF へ戻しています
（そのままだと保存のたびにファイル全体の改行コードが変わってしまいます）。

## 新規ページ

存在しないページの編集画面を開くと、空の状態で始まり、保存すると作成されます。
保存先の拡張子は選ばれている記法のもので、初期値は既定の書式
（`DEFAULT_MARKUP`、いまはPukiWiki記法＝`.txt`）です。

## 更新順の一覧（recent）

DBが持つ最終更新日時から引きます。**専用の記録ページは持ちません。**

以前は `RecentEditFiles` というページに保存のたびに書き足していました。
一覧を出すたびに全ページを走査したくなかったためですが、DBが更新日時を持つように
なったので、その役目は終わりました。

記録ページを廃したことで、それに付いていた次の制約や例外も無くなりました。

| 以前あったもの | なぜ要ったか |
|---|---|
| 件数の上限（既定50） | ページが際限なく伸びるのを防ぐため |
| 削除されたページを一覧から取り除く処理 | 消えたページが一覧に残らないように |
| **記録ページ自身の更新を無視する特別扱い** | 記録ページを書き換えること自体が更新になり、毎回1件を消費してしまうため |

いまはどれも不要です。全ページが対象で上限が無く、消えたページはDBの行ごと
消えるので、後から取り除く手当ても要りません。

一覧は `#recent` プラグインがDBの並びから作ります。
