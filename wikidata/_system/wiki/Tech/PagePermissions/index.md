# ページごとの権限

閲覧権限・編集権限の仕組みと、それを決めるまでの調査・判断の記録です。
前半が現在の仕様、後半（「調査の時点の検討」以降）が2026-09-13の調査の記録で、
その後に決まったことは各項目に「→」で書き添えてあります。

## 目指す枠組み

設計者が示した要件です。

1. 未ログインには編集権限を認めない。閲覧・検索など参照だけ
   （既定にはしていません。Wikiを作った直後はアカウントが無く、誰も書けなくなるためです。
   権限の既定の行 `*:W:g:all` を置いたときの動きです。下の「編集の権限と、未ログインの扱い」）
2. 編集には最低でもログインが要る
3. 特定ページでは閲覧ユーザを制限できる
4. 閲覧権限がないページには編集権限を与えない（編集できる人は閲覧できる人の部分集合）
5. さらに別途、編集権限を制限できる
6. 閲覧権限がないページは検索結果から省く

4 により、判定は「閲覧の可否 → 編集の可否」の1本の流れになります。閲覧できない相手に
「編集できません」と返すと、ページの存在を教えてしまうためです。

## 決まったこと

### 守りの強度は「見せたくないものを隠す」

設計者の言葉で「認証は『見せたくないものを隠す』の意図です」。**秘密を守る仕組みでは
ありません。** 本文は平文ファイルに残ったままという前提と釣り合う強さで作り、機密文書を
置く場所としては設計しません。

### アカウント作成は誰でも通るまま

「誰でも編集できるページ管理システム」という性格から、登録の入口は絞りません。代わりに、

- 必要なページだけ特定ユーザに絞る
- バックアップで内容を戻せるようにする
- 疑わしいユーザによる作業の一覧を出せるようにする（未実装）

の3つで受けます。Wikiごとに承認制（`account.policy: approval`）も選べます。既定は `open`
（[アカウントの仕組み](/Tech/Accounts) の「ユーザ登録の受け入れかた」）。

### プラグインによる書き換えは、ユーザの編集とは別に数える

`#comment`・`#vote`・`#tasklist` による本文の書き換えはユーザの編集とは別に扱い、
書き換え者を `system` として記録します。

- `#comment`・`#vote` は、閲覧できれば編集の権限が無くても使えます。「未ログインには編集権限を認めない」も
  これらを止めません
- `#tasklist` のチェックの切り替えは、編集の権限（`W`）がある人だけです（設計者の指示、2026-09-25）

### ファイルの直接操作は admin とみなす

サーバー上でのファイル操作や `./wiki.py updatepage` による取り込みは admin 権限とみなし、
編集者 `admin` として記録します。

### パスワードのハッシュは「塩＋ユーザ名＋パスワード」

`1234` のようなありふれたパスワードを複数の人が使ったとき、同じハッシュ値から互いに
露呈しないようにするためです（設計者の指示、2026-09-21）。`account.pw_salt`＋`uid`＋パスワードを
`\x00` を挟んで連結します。`pw_salt` の既定（空）は Wiki名で、Wiki名を変えるときは旧名を
`pw_salt` に固定してから移します。旧い形のハッシュは通しません。詳しくは
[アカウントの仕組み](/Tech/Accounts) の「パスワードの持ちかたと、その弱さ」。

### 権限を与えられるのは、ページ編集者と助手だけ

グループは誰でも作れますが、そのグループに権限を与えられるのはページの編集者か助手です。

未知のユーザ・グループを指定するとエラーにします。存在しないグループ名を書いておくと、
後からその名前で作った相手に権限が渡るためです。`/.admin/privileges` からの登録と
`#readauth`・`#writeauth` からの書き出し（`plugin/_authcommon.py` の `_parse_users`）の両方で断ります。

### `/.restart`・`/.newwiki`・`/.allwiki` は既定Wikiの `admin` と `g:staff` だけ

ページの権限とは別の話です（[再起動の仕組み](/Tech/Restart)・[新しいWikiを作る仕組み](/Tech/NewWiki)）。
`/.delwiki`（[Wikiを消す仕組み](/Tech/DelWiki)）も同じ判定を通ります。`/.allwiki` は読むだけの
画面ですが、並ぶWiki名がそのままURLなので同じ扱いにしています（[Wikiの一覧](/Tech/Reference/Views#wikiの一覧)）。
既定Wikiが持つ役割のまとめは [設計方針](/Tech/DesignPolicy/Farm#デフォルトのwikiの役割) にあります。

**Wiki名を含むURLは、既定Wikiのものでも403で断ります**（設計者の指示、2026-09-13。
「default wiki が dwiki のとき、`/=dwiki/.restart` なども禁止扱い」）。はじめは既定Wikiの
URLへ送り直していましたが、断る形に改めました。ログインのcookieはWikiごとの `Path` に
あるので、素のURLだけに絞れば、読まれるcookieが既定Wikiのものひとつに決まります。

### 新規設置のときは、新しく作ったWikiが既定になる

`_system` のような `_` で始まるWikiは、`config/server.yaml` を直接編集しない限り既定Wikiに
できないようにする予定です（**未実装**）。既定Wikiを移すと、`/.restart` などの権限の
持ち主も移るためです（[新しいWikiを作る仕組み](/Tech/NewWiki) にも注意書きがあります）。

## 権限をどこに持つか

**ページの権限は、本文とは別のデータ（`config/privileges`）として持ちます。**
`#readauth` のように本文に書く方式では、止めるかどうかが描画してみないと分からず、
検索から省くには全ページを描画することになるためです。

調査の時点の候補と、それぞれの引っかかり:

| 置き場所 | 引っかかり |
|---|---|
| `pageinfo/wikiall.db`（`pages`表に列を足す） | このDBは平文ファイルから作り直せる前提（`pagedb.rebuild`）。作り直すと権限が消える |
| `config/users.db` に新しい表 | 作り直しの対象外だが、ページの移動・改名への追随が要る |
| `config/` のテキスト | 手で読める・直せる。ページ数が増えたときと、画面から書き換えるときの競合が課題 |
| ページの平文ファイル側（frontmatter等） | 改名に強いが、本文を読まないと権限が分からず、検索で同じ問題に戻る |

設計者の案で `config/` のテキスト（`config/privileges`）にしました（形式は下の「sqlite かテキストか」）。
