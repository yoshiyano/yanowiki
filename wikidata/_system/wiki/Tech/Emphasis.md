# 日本語の `**強調**` が効くようにしてある

Markdown（CommonMark）は、`*` の並びが開き側・閉じ側になれるかを前後の文字の種類
（空白・約物・それ以外）で決めます。これは単語を空白で区切る言語が前提なので、日本語では
効いてほしい書きかたが落ちます。そこで、CommonMark の判定を1段ゆるめてあります
（Wiki設計者の指示、2026-09-06。実装は `_sys/wikilib/cjkemphasis.py`）。

## 落ちていた書きかた

```markdown
文言に**「ロックまで残りn回」**を添えます
- **前提としているハードウェアの癖。**WDT のタイムアウトが 2.2 秒であること
**見出し一覧（目次）**を差し込む
```

開き側の `**` の直後が全角の開きかっこ、閉じ側の `**` の直前が全角の句点で直後が半角英字、
といった形です。

## どうゆるめたか

**`*` の外側が全角の文字・約物なら、開き側（閉じ側）になれることにします。**

| | |
|---|---|
| 直後が全角 | 開き側になれる |
| 直前が全角 | 閉じ側になれる |

全角として扱うのは、ひらがな・カタカナ・漢字・ハングル・全角の英数・全角の約物
（`。` `、` `「` `」` `（` `）` `〜` など）です。全角の空白（U+3000）は空白として扱います。

考えかたは JavaScript の `markdown-it-cjk-friendly` と同じで、判定を真にする側にしか動かしません。
もともと効いていた書きかたの結果は変わらず、`2 * 3 * 4` や `snake_case_word` も飾りになりません。

## 効く範囲

`markdown_it` の `StateInline.scanDelims` を差し替えているので、この処理系で描くものすべてに効きます。
Wikiごとの設定にはしていません（Wikiごとに別の処理系を組み立てる必要があり、ゆるめる方向にしか
動かないので切る場面も考えにくいため）。

## 確かめかた

`tests/test_cjkemphasis.py` が、落ちていたものが効くことと、効いていたものが変わっていないことの
両方を見ています。
