# writeauth — ページを編集できるユーザを指定する

| 使える記法 | |
|---|---|
| ブロック `#writeauth()` | ○ |
| インライン `&writeauth();` | × |

呼びかたのルールは [共通の書きかた](/Syntax/Common#プラグインの呼びかた) をご覧ください。

#code()

ページを編集できるユーザを、ページの中に書いて指定します。編集できる人は、そのページを読めます（編集の権限は閲覧を含みます）。
閲覧を制限したいときは [readauth](/Syntax/Plugin/readauth) を使います。

書いた内容は `config/privileges.plugin` に権限として記録され、管理画面 `/.admin/privileges` で登録する権限と同じように効きます。ページには何も表示されません。

### 書きかた

```pukiwiki
#writeauth(id1,id2,...)
```

| 引数 | 書式 | 既定 | 意味 |
|---|---|---|---|
| `users` | ログインIDか `g:グループ名` を `,` 区切りで列挙 | （省略すると、記録を削除） | 編集を許可するユーザ |

- 実在しないユーザ・グループを書くとエラーになります（あとから同じ名前で作られた人に権限が渡らないように）
- **書く人は、許可者に自分を入れてください。** 入っていないと、書いた本人も編集できなくなります

### 記録される内容

`Tech/Secret` に `#writeauth(alice,bob)` と書くと、次の1行が記録されます（行の形は手で書く `config/privileges` と同じ）。

```text
Tech/Secret:W:alice,bob:260921_103000
```

「ページ名:種類:許可者:登録日」の並びで、`W` は編集（`#readauth` は `R`）です。ページ名はいつも書いたページ自身です。
`#readauth(alice,bob,carol)` と両方書けば `R` と `W` の2行になり、`alice` は読み書き、`bob`・`carol` は読むだけになります。

`config/privileges` より優先され、緩める方向には働かない点は [readauth](/Syntax/Plugin/readauth) と同じです。

### 権限を消す

1. `#writeauth()`（空の呼び出し）にして、ページを開きます。記録の該当行が削除されます
2. そのあと、`#writeauth()` の行をページから消します

行だけを消した場合も、記録は1時間以内に自動で消えます。すぐに消したいときは `/.updatePageAuth` を
開きます（誰でも実行できます。1時間に10回まで）。ページを削除したときの記録も同じく消えます。

### 置ける場所は、ページの一番上だけ

途中に書くと、ページを開いたときにその行が先頭へ移ります（本文が書き換わります）。
扱いは [readauth](/Syntax/Plugin/readauth#置ける場所はページの一番上だけ) と同じです。

- `#readauth` と両方あれば、`readauth`、`writeauth` の順に並びます
- 同じプラグインが複数行あれば、最初の1行だけが残ります
- Markdownのページで先頭にタイトル行（`# 見出し`）があれば、そのすぐ下へ移ります
- 編集中のプレビューでは、移動も記録の書き換え・削除もしません（エラーは確かめられます）

### エラーについて

| 書きかたの例 | エラーになる理由 |
|---|---|
| `#writeauth(nobody)` | 実在しないユーザ（`g:` のグループも同じ） |
| `#writeauth(alice)`（記録が書けないとき） | `config/privileges.plugin` に書き込めない。**このままでは制限が効きません** |
| 名前に `*` を含むページに書いた | ワイルドカードと区別が付かず、記録できない |

書きかた自体が壊れている場合は、共通のエラーになります（[共通の書きかた](/Syntax/Common#うまく動かないとき) 参照）。
