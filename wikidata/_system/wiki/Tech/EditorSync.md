# 外部エディタ連動

編集画面とセクション編集の本文を、手元のエディタ（VS Code・Emacs・Neovim）と同期する仕組みです。使いかたは
[外部エディタ連動の編集](/PageEdit/EditorSyncGuide)。

## 全体の構成

編集画面と、手元のエディタのプラグインが、専用のプロトコル（下の「プロトコル v1」）で話します。
エディタのプラグインが WebSocket で待ち受け、編集画面がつなぎに行きます。

#img(全体の構成（① 直接つなぐ・② 拡張機能を通す）>architecture.svg)

- ① は、ページの JavaScript から直接つなぐ。社内などの LAN にある Wiki ではこれで足りる
- ② は、インターネットに公開した Wiki を http で開いたとき。ブラウザがページから手元への通信を
  断るので、拡張機能が代わりにつなぐ（下の「調べたこと」）。拡張機能がインストールされていて、そのサイトを
  許していれば、LAN の Wiki でも ② を使う
- **状態と画面は Wiki 側**（`editor.link.js`）が持つ。拡張機能は中身を見ずに中継するだけ。
  本文の同期・食い違いの解決は、編集画面とプラグインの2者で行う

| 置き場所 | 中身 |
|---|---|
| `_sys/editor/editor.link.js` | 連動の中核 `WikiEditorLink.attach`（つなぐ・状態・本文とカーソルの同期・画面）と、編集画面へのつなぎこみ |
| `theme/common.js`・`common.css` | セクション編集へのつなぎこみ（連動のボタンの場所・つないでいるあいだ入力欄を隠す） |
| `_sys/editor/editor.js`・`editor.css` | プレビューの位置合わせ（入力欄を隠したとき）・入力欄とツールバーを隠す |
| `PageEdit/EditorSyncGuide/BrowserExt` の添付 | ブラウザ拡張機能の元のファイル（zip は Chrome・Firefox の各ページの添付） |
| `PageEdit/EditorSyncGuide/VSCode`・`Emacs`・`Neovim` の添付 | エディタのプラグイン |

プラグインや拡張機能は、この Wiki の添付として管理し、ここから配布する（設計者の決定、2026-10-06）。
添付はフォルダを持てないので、ページの階層をフォルダとして使う（子ページ1つが1つのフォルダ）。

## ブラウザ側（editor.link.js）

編集画面に「外部エディタにつなぐ」のボタンや状態の表示を足し、エディタとの同期を受け持つ。

### 状態

| 状態 | 画面の表示 | 次へ |
|---|---|---|
| `off` | 「外部エディタにつなぐ」 | 押すと `waiting` |
| `waiting` | 「エディタを待っています…」 | つながって `welcome` が来たら `connected`。つながらなければ 2・4・8 秒、以後 10 秒ごとに再試行し続ける |
| `connected` | 「エディタとつながっています（エディタの名前・プラグインのバージョン）」 | 切れたら `waiting`（エディタが止まった）。`closed` が来たら `closed` |
| `closed` | 「エディタ側で閉じました［もう一度つなぐ］」 | この画面では自動でつなぎ直さない |

- オン・オフはブラウザの localStorage（`wikiEditorLink`）が覚え、オンなら編集画面を開くたびに
  つなぐ。ほかのタブで切り替えたら、`storage` イベントでこの画面も合わせる。オフにするのは
  「切断」を押したときだけ
- エディタのポート番号は localStorage（`wikiEditorLinkPort`、既定 4100）
- タブのセッション ID（`session`）は sessionStorage（`wikiEditorLinkSession`）。同じタブなら、保存や
  ページの切り替えで再読み込みしても同じセッション ID で、プラグインはそれを見て同じバッファを使い続ける

### つなぐ相手の選びかた

拡張機能が `<html data-wiki-editor-relay>` 属性を付けていれば、拡張機能を通す（`relayTransport`）。
無ければ `ws://localhost:<ポート番号>/` へ直接つなぐ（`directTransport`）。どちらも
`open(info, handlers)` で `{send, close}` を返す同じ形にしてあり、上の処理は相手を区別しない。
拡張機能はページより後に属性を付けることがあるので、開いてから 150 ミリ秒待って始める。

### 本文とカーソル

- つながったら `hello` で、セッション ID・ページ（パス・名前・書きかた・URL）・全文・ハッシュ・
  本文を最後に変えた時刻・添付ファイルの一覧を送る
- 本文の入力欄（`textarea.edit-source`）の値が基準。手元で変わったら、150 ミリ秒待って、シャドウ（最後に
  そろえた本文）との違いを `edit` で送る。`input` を出さずに書き換えるツールバーなどに備えて、
  1 秒ごとにも見る
- エディタから `edit`・`full` が届いたら、入力欄の値を差し替えて `input` を出す（下書き・プレビュー・
  保存ボタンの状態は `input` を見て動く。`editor.js`）。こちらのカーソルは、変わった位置に合わせて
  ずらす
- カーソルは、入力欄で動かしたら 200 ミリ秒待って `cursor` で送る（打った分は本文と一緒に送る）。
  エディタから届いたら入力欄のカーソルを合わせ、そこが見えるようにスクロールする
- ハッシュ（SHA-256）は JavaScript で計算する。ブラウザの `crypto.subtle` は https か localhost の
  ページでしか使えないため
- 本文を最後に変えた時刻は、編集画面を開いた時刻から始める。保存で再読み込みしたとき、保存した結果
  （`&date;` の展開などでサーバーが変えたもの）を正とするため
- 食い違って `full` で置き換えたときは、置き換える前の本文を localStorage（`wikiEditorLinkBackup`）に
  バックアップする
- 添付ファイルの一覧は、添付タブの行から集める。`ref` は添付タブの「本文での書きかた」をそのまま
  使う（決まりを `editor.py` の `attach_ref_text` の1か所に保つため）。添付を操作すると編集画面が
  再読み込みされるので、一覧もそのたびに新しくなる
- エディタから `save` が届いたら（設計者の指示、2026-10-13）: 変更が無い（「保存」が押せない）なら、
  「一時中断」を押して編集を終える。変更があれば「保存」を押す。「連続編集」がオンなら、そのまま
  再読み込みして編集を続け、オフならページの表示へ戻る。編集を終えるとき（変更なし・連続編集が
  オフ）は、離れる直前に `reload` ではなく `bye` を送り、エディタのバッファも閉じる（`saveFromEditor`）

### 離れるとき

編集画面が自分で送信して離れるとき（保存・サイドバーでのページの切り替え・添付の操作）は、
`pagehide` で `reload` を送って切る。プラグインはバッファを保ち、同じセッション ID の `hello` を待つ。
ただし、編集を終えて通常表示に戻る送信（「一時中断」、連続編集がオフのときの「保存」「内容破棄」）は、
編集画面が戻ってこないので `bye` を送り、エディタのバッファもすぐ閉じる（どの送信かは、押されたボタンか
`cmd` で見る。`reload` を送っていたころは、エディタが戻りを待って 10 秒たってから閉じていた。設計者の
報告、2026-10-13）。
`reload` のあとに切れたのは、いつもの再読み込みなので、エディタは「通信が切れた」とは知らせない
（2026-10-13 に足した。それまでは `bye` を送らずに切るだけで、エディタは保存のたびに本当の切断と
見分けられず「切断」と知らせていた。設計者の報告）。それ以外で
離れるとき（タブを閉じた・リンクでほかのページへ移った）は、`pagehide` で `bye` を送り、
プラグインはすぐバッファを閉じる（設計者の指示、2026-10-07）。

ブラウザからは、タブを閉じたのか再読み込みなのかをイベントだけでは見分けられないので、送信の有無で
見分ける。送信は、ボタンによるもの（`submit` のイベント）と、プログラムからの `form.submit()` の
両方を見る（後者はイベントが出ないので、関数をラップする）。送信してもページが移らない場合に備えて、
フラグは 10 秒で消す。

### つないでいるあいだの画面

本文の入力欄とツールバー（書式ボタン・書きかたの選択）を隠し、プレビューを広げる（設計者の指示、
2026-10-08・10-10）。`editor.link.js` が `.page-editor` に `data-editor-link-hidden` を付け、
`editor.css` が消す。書きかたの切り替えはエディタに伝える仕組みが無いので、書きかたも隠す（変えるときは
切断してから）。

プレビューの位置合わせ（`editor.js`）は、本文の入力欄のスクロールを手がかりにしている。入力欄を隠して
いるあいだは、カーソルのある行に合わせる。エディタからカーソルが届くと、`editor.link.js` が入力欄に
`wiki-editor-caret` イベントを出し、`editor.js` が合わせ直す。隠れた入力欄（幅 0）の行の位置は測らない
（1字ずつ折り返した複製を組むことになり、長いページで重い）。

クロコの案（設計者は未確認）: 隠すのはつながっているあいだだけ（待っているあいだに隠すと、
エディタを起動していない日は切断するまで書けない）。保存などで再読み込みするたびに出たり消えたり
しないよう、このタブで直前までつながっていたら（sessionStorage の `wikiEditorLinkHidden`）隠した
まま始め、つながらなかったら出す。

## セクション編集

セクション編集（`theme/common.js`）も、編集画面と同じ中核 `WikiEditorLink.attach` を使う。中核は、本文の欄・
ボタンを置く場所・隠す印を付ける要素・ページの情報・保存の動作を受け取り、上の「状態」「本文とカーソル」の
とおりに動く。プロトコルもエディタのプラグインも変えていない。

- **読み込み:** 表示のページには `editor.link.js` を入れておかず、セクション編集を開いたときに `/.editor.link.js` を
  読み込む（ふつうに読むだけの人には要らないため）。読めなければ、連動のボタンを出さない
- **ボタンの場所:** 「保存」「閉じる」の右（設計者の指示、2026-10-27）。見た目は `common.css` の `.section-editor .edit-link`
- **隠す:** つないでいるあいだ `.section-editor` に `data-editor-link-hidden` を付け、入力欄を隠してプレビューだけにする
  （設計者の指示、2026-10-27）。再読み込みをまたいで隠したまま始める仕組み（編集画面の `wikiEditorLinkHidden`）は使わない。
  セクション編集は再読み込みで閉じるため
- **ページの情報と添付:** 表示のページには書きかたの選択も添付タブも無いので、節の取り出し（`/.section/<ページ>?parts=1`）の
  返事に `page`（書きかた・拡張子・URL）と `attachments` を入れてもらう（[セクション編集の仕組み](/Tech/SectionEditing#開くとき)）。
  エディタに見せる名前（`title`）は「ページ名#見出し.拡張子」
- **セッション ID:** 開くたびに新しく作る。編集画面のバッファとも、前に開いた節のバッファとも別になる
- **オン・オフ:** 編集画面と同じ localStorage（`wikiEditorLink`）。オンなら開いたときに自動でつなぐ。「切断」を押すと、編集画面でもオフになる
- **エディタからの保存:** 「保存」を押したのと同じ。変更があれば保存してページを読み直し、無ければ閉じる
- **離れるとき:** 「閉じる」・保存して読み直す・タブを閉じる、のどれでも `bye` を送り、エディタのバッファも閉じる。
  セクション編集は読み直しで閉じるので、`reload` は送らない

## ブラウザ拡張機能（中継）

元のファイルは `PageEdit/EditorSyncGuide/BrowserExt` の添付。Manifest V3。

| ファイル | 役目 |
|---|---|
| `relay.js` | コンテンツスクリプト。ページに `data-wiki-editor-relay` 属性を付け、ページとバックグラウンドのあいだで、`window.postMessage` と `runtime.Port` のメッセージを中継する。中身は見ない（形だけ確かめる） |
| `background.js` | バックグラウンド（service worker）。エディタへの WebSocket を持つ。ツールバーのボタンで、そのサイトの許可を求め、許したサイトに `relay.js` を挿入するよう登録する |

ページとの中継のメッセージの形（`editor.link.js` の `relayTransport` と同じ）:

```
ページ → 拡張機能  {wikiEditorRelay: "open", id, port} / {... "send", id, data} / {... "close", id}
拡張機能 → ページ  {wikiEditorRelay: "opened" | "message" | "closed", id, data?, wasOpen?}
```

- 許可は、閲覧者がボタンを押したときに、そのサイトだけ求める（`optional_host_permissions`）。
  `localhost`・`127.0.0.1` への通信は、はじめから持つ
- Chrome は、イベントが無いとバックグラウンド（service worker）をしばらくで止め、持っている
  WebSocket も切れる。つないでいるあいだ、`relay.js` が 20 秒ごとにキープアライブのメッセージを送り、止まらないようにする
- 拡張機能を通すと、プラグインに届く `Origin` は拡張機能のもの（`chrome-extension://…`・
  `moz-extension://…`）になる。プラグインは拡張機能からの接続を受け付ける代わりに、`hello` の
  ページの URL のオリジンで許すかを決める
- ブラウザごとの zip にして配布する（`build_zip.py`）。Chrome は MV3 で `background.scripts` を
  エラーにし、Firefox は `background.service_worker` で動かないので、マニフェストだけを入れ
  替える。Firefox で署名を受けるための項目は [Firefox](/PageEdit/EditorSyncGuide/Firefox)

## エディタのプラグイン（共通の作り）

3つのプラグインは、同じ作りを各エディタの言葉で書いたもの。どれもほかのパッケージに頼らず、
WebSocket の待ち受けも中に持つ。

- **待ち受け**: `127.0.0.1:<ポート番号>`（既定 4100）。HTTP の接続を受け、WebSocket に切り替える
  （`Sec-WebSocket-Accept` は WebSocket の決まりで SHA-1 と base64）。フレームの分割・マスク・
  ping に応じる
- **オリジンの確認**: `Origin` が `http://localhost`・`http://127.0.0.1`（ポート番号は問わない）なら受ける。
  覚えたものも受ける。知らないものは、接続の応答を保留して閲覧者に尋ね、許せば覚え、断れば
  そのエディタを閉じるまで覚えて 403 を返す。同じオリジンの接続が重なっても尋ねるのは1回。
  WebSocket には CORS がかからず、どのサイトのページからでも localhost につなげるので、確かめないと
  開いただけのサイトにエディタを読み書きされうる
- **セッション ID ごとのバッファ**: `hello` のセッション ID で、同じバッファ（VS Code ではドキュメント）を使い続ける。編集画面との
  つながりが `bye` なしで切れたら、10 秒（`keep-seconds`）待ち、同じセッション ID の `hello` が来たら
  引き継ぐ。来なければ閉じる
- **新しいページ**（初めて・同じタブで別のページ）: 本文を読み込み、名前とモードをページに合わせ、
  カーソルを先頭に置く。同じページを引き継いだときは、本文もカーソルも動かさない
- **本文の置き換え**（新しいページ・`full`）も、前後で共通する部分を除いた1か所だけを書き換える
  （本文の長さに比例する時間で済む）。Emacs の `replace-buffer-contents` は違いを細かく調べるので、
  中身の違う長い本文では何分もかかり、そのあいだ Emacs 全体が止まっていた（2026-10-13 に直した。
  25 行で 0.6 秒、100 行で 43 秒、3000 行では終わらなかった）
- **差分**: シャドウとバッファの本文を比べて、共通の前後を除いた1か所を `edit` で送る。150 ミリ秒
  待ってから送り、そのあとカーソルも送る
- **切れているあいだの編集**: 通信が切れても編集は止めない。状態は「つながっている・再読み込み中・
  応答なし・切断」の4つで、エディタの中で編集を止めない形で見せる（Emacs はモード行の ` Wiki` を
  ` Wiki:再読み込み中`・` Wiki:応答なし`・` Wiki:切断` に。VS Code はステータスバーの項目、応答なしと
  切断は警告の背景色。Neovim はそのウィンドウの上の行（winbar）と `vim.b.wikiedit_state`。未送信の分が
  あれば印を付ける）。
  編集画面は 20 秒ごとに `ping` を送るので、45 秒何も届かなければ「応答なし」とし、変更は送らずに
  ためておく（相手が受け取らないまま送ると、送り終わるまでエディタが待ち続けるため）。何か届いたら
  送る。送っていない変更があるあいだは、待つ時間（10 秒）を過ぎてもバッファを閉じない。
  編集画面から `reload` が届いたあと（または、エディタから保存を送って 15 秒以内）に切れたときは、
  いつもの再読み込みとして「再読み込み中」とし、知らせない。待つ時間を過ぎても戻らないときに「切断」とする。
  つなぎ直したときの合わせかたは、下の「食い違ったとき」。設計者が承認したクロコの案（2026-10-13
  「その案で、まず Emacs から進めてください」。VS Code・Neovim は 2026-10-14「VS Code と Neovim も
  同じ形にしてください」）。VS Code（Node）の HTTP の待ち受けは、相手が送信を閉じても（FIN）自分からは
  閉じないので、`end` を受けたらすぐ切れたものとして扱う（そうしないと、送って失敗するまで気付かず、
  そのあいだの変更が失われていた）
- **ポートの引き継ぎ**: ポートがふさがっていたら（ほかのエディタが待ち受けている）、5 秒ごとに
  取り直そうとし、空いたら待ち受ける
- **エディタ名の表示**: `welcome` の `editor` に「エディタの名前とバージョン・wikiedit の更新日時」を含め、編集画面に出す

### VS Code の拡張機能の作り

クロコの案を、設計者が承認した（2026-10-08）。

- **ドキュメント**は `wikiedit://<Wiki のホスト>/<ページ名>.<拡張子>`。中身はメモリに持つ
  （`FileSystemProvider`）。拡張子で言語が決まる（設定 `wikiedit.languages` で書きかたごとに替えられる）。
  同じページを別のタブの編集画面でも開いたら、URI にセッション ID を足して別のドキュメントにする
- **保存**: 手動で保存（`onWillSaveTextDocument` の `reason` が `Manual`）したら `save` を送る。
  本文は打つたびに送っているので、未保存のマークは、拡張機能がバックグラウンドで保存して消す（閉じる
  ときに訊かれないように）。保存のときに本文を変える設定（`editor.formatOnSave`・
  `files.trimTrailingWhitespace`・`files.insertFinalNewline`・`files.trimFinalNewlines`・
  `editor.codeActionsOnSave`）があれば、勝手に本文を変えないよう、マークを残す
- **差分**はシャドウとドキュメントの本文を比べる（`contentChanges` は使わない。複数のカーソルの変更も1つに
  まとまる）。届いた変更は、ドキュメントの本文との差分にして1回の `WorkspaceEdit` で当てる。当てるのは
  非同期なので、届いたメッセージは1つずつ順に扱い、当てているあいだは手元の変更を送らない
- **閉じる**: タブが無くなったこと（`tabGroups.onDidChangeTabs`）で知る（`onDidCloseTextDocument` は
  ドキュメントの中身が捨てられたときに来るもので、タブを閉じたときとは限らない）
- **ページの切り替え**: 新しいページのドキュメントを前のドキュメントと同じ場所に開き、前のドキュメントを閉じる（ドキュメントの
  名前は替えられないため）
- **許したオリジン**は設定 `wikiedit.allowedOrigins`。`scope: "application"` にして、ユーザーの設定に
  だけ書けるようにする（開いたフォルダの `.vscode/settings.json` が許すオリジンを足せないように）
- 改行は設定（`files.eol`）によって CRLF になるので、開いたときに LF にそろえる。開発用の
  リモート（SSH・WSL など）では拡張機能がリモート側で動き localhost が違うマシンになるので、
  `extensionKind: ["ui"]` で手元側で動かす（リモートでは確かめていない）
- `.vsix` は `build_vsix.py` が `package.json`・`extension.js` からビルドする（マニフェスト
  `extension.vsixmanifest` も package.json から作る。`vsce` は要らない）

### Neovim のプラグインの作り（クロコの実装例。設計者は未確認）

- **1つのファイル**を `~/.config/nvim/lua/` に置き、`require("wikiedit").setup()` で始める（Wiki の
  添付1つで配れるように）。待ち受けは `vim.uv or vim.loop`、WebSocket の SHA-1 と base64 は Lua で
  書いた（`vim.base64` は 0.10 から）。本文のハッシュは `vim.fn.sha256()`。`vim.uv` の呼び出し元
  から Neovim の API を呼ぶときは `vim.schedule` を通す
- **本文**は行を `\n` でつないだもの。行に分けて持つので、Vim の「最後の行の改行」（`eol`）は本文に
  入らず、本文の最後の改行は空の最後の行として、そのまま保つ
- 変更は `nvim_buf_attach` の `on_lines` で知る。届いた変更は `nvim_buf_set_text` で1か所だけ書き換える。
  本文は打つたびに送るので、変更フラグ（`modified`）は消しておく
- **閉じる**: `:bd` で閉じたら `closed` を送る。ウィンドウを閉じただけではバッファは残る。`:bd` は名前を
  残したままにするので、同じページをもう一度開いたときに名前がぶつからないよう、消し切る（wipe）
- **カーソル**は位置だけを送る（Visual モードの範囲は送らない）。添付の書きかたはカーソルの後ろに
  挿入する（`p` と同じ向き）。キーは割り当てず、コマンドだけを持つ。表示方法の既定は新しいタブページ

## プロトコル v1

クロコの案を、設計者が承認した（2026-10-08「クロコ案OKでした」）。

### つなぎかた

- エディタのプラグインが `ws://localhost:<ポート番号>/` で待ち受け（既定 4100。atomic-chrome の 4001 とは
  分ける）、ページ（か拡張機能）がつなぐ
- メッセージは JSON で、WebSocket の text のフレーム1つに1つ。どれにも `type` と、送った側の
  時刻 `t`（ミリ秒）を付ける

### 本文の表しかた

- 本文は改行を LF にそろえた文字列。位置は UTF-16 の単位で数える
- ハッシュは、その本文の UTF-8 のバイト列の SHA-256（16進の小文字）
- 双方が「最後にそろえた本文」（シャドウ）を持つ。手元で変わったら、シャドウとの違いを差分として送り、
  シャドウを新しくする。ハッシュは変更前と変更後の両方を添える（変更後で、位置の換算の誤りも見つけられる）

### メッセージ

| type | 向き | 中身 |
|---|---|---|
| `hello` | ページ → エディタ | `session`（タブのセッション ID）・`page`（`path`・`title`・`markup`・`url`）・`text`・`hash`・`modified`・`attachments`（添付ファイルの一覧。1件ごとに `name`・`kind`・`size`・`mtime`・`ref`（本文での書きかた）） |
| `welcome` | エディタ → ページ | `editor`（エディタの名前）・`resumed`（同じセッション ID のバッファを引き継いだか）・`hash`（`hello` で届いた本文のハッシュ。エディタの変更は、このあとの `edit` か `full` で送る）・`modified`・`t_recv`（hello を受けた時刻） |
| `edit` | 両方 | `from`（変更前のハッシュ）・`to`（変更後のハッシュ）・`changes`（`{start, end, text}` の列。前から順に当てる）・`modified` |
| `state` | 両方 | `hash`・`modified`。ハッシュが合わないときに送る |
| `full` | 両方 | `text`・`hash`・`modified` |
| `cursor` | 両方 | `start`・`end` |
| `save` | エディタ → ページ | エディタから保存を押す |
| `ping` / `pong` | ページ → エディタ / エディタ → ページ | `pong` は `t0`（ping の t）・`t1`（受けた時刻）・`t2`（返した時刻） |
| `clock` | ページ → エディタ | `offset`（エディタの時刻 − ページの時刻。ミリ秒） |
| `bye` | ページ → エディタ | 切断を押した・タブを閉じた。エディタはバッファを閉じる |
| `reload` | ページ → エディタ | 編集画面が自分で送信して再読み込みする（保存・ページの切り替え・添付の操作）。同じセッション ID の `hello` で戻る。エディタは、このあとに切れても「通信が切れた」とは扱わない（2026-10-13 に足した。知らないエディタは読み飛ばす） |
| `closed` | エディタ → ページ | エディタ側でバッファを閉じた |

`modified` は、その本文を最後に手元で変えた時刻（送った側の時刻）。

### 食い違ったとき

1. `edit` の `from` が自分のシャドウのハッシュと合わない、または当てた結果が `to` と合わなければ、
   `state` を送る
2. `state` を受けた側は、ハッシュが同じなら何もしない。違えば `modified` を比べ（相手の時刻は
   時刻のずれで直して比べる）、**自分が新しければ `full` を送る**。相手が新しければ、まだ
   送っていなければ自分の `state` を返す（新しい側がそれを受けて `full` を送る）。同じ時刻なら
   エディタ側を正とする
3. `full` を受けた側は本文を置き換える。置き換える前の本文は消さずにバックアップする（ページは
   ブラウザに、エディタは「控え」という名前のバッファに）

`hello` で引き継いだとき（`resumed`。通信が切れてつなぎ直したとき・保存などで再読み込みしたとき）は、
最後にそろえた本文（シャドウ）を知っているエディタが、`welcome` を返す前に決める（2026-10-13 に
Emacs、2026-10-14 に VS Code・Neovim）。

| 切れているあいだに変わったもの | エディタがすること |
|---|---|
| エディタだけ（バッファ ≠ シャドウ、`hello` の本文 ＝ シャドウ） | `welcome` のあとに、シャドウからの差分を `edit` で送る（時刻は比べない） |
| 編集画面だけ（バッファ ＝ シャドウ） | バッファを `hello` の本文にそろえる |
| 両方 | `modified` を比べる。編集画面が新しければバッファを `hello` の本文にそろえ、エディタの分は控えのバッファに残す。エディタが新しければ `welcome` のあとにバッファの全文を `full` で送る（編集画面は自分の分をブラウザに控える） |

`welcome` の `hash` は、いつも `hello` で届いた本文のハッシュにする。編集画面は `welcome` で食い違いを
見つけないので、時刻で決め直さない。前の決まり（エディタの本文のハッシュを返し、編集画面が時刻で決める）
では、切れているあいだの変更が待つ時間で消える・次に打つまで届かない・`full` の直前に送った `edit` で
両者の本文がずれる、が起きていた。`full` を受けたときは、置き換える前に手元の分を送らない（控える）。

### 時刻のずれ

ページは `ping` を送り、`pong` の `t0`・`t1`・`t2` と受けた時刻 `t3` から、ずれを
((t1 − t0) + (t2 − t3)) / 2 と推定する（NTP と同じ推定のしかた。つないだときと、20 秒ごと）。
推定値は `clock` でエディタにも知らせる。20 秒ごとの `ping` は、つながりが生きているかの確かめも
兼ねる。

### 再読み込み（保存・ページの切り替え）

編集画面が自分で送信して離れるときは `bye` を送らずに切れ、エディタはバッファを 10 秒保つ。同じ
`session` の `hello` が来たら引き継ぐ（ウィンドウを作り直さない）。ページが違えば、バッファの名前とモードを
新しいページに合わせる。10 秒たっても来なければ閉じる（`bye` が届かなかったときの備え）。
見分けかたは上の「離れるとき」。

## 調べたこと

### ページから localhost へ直接つなげるか（2026-10-06、Chrome 154・Firefox 157）

| ページの置き場所 | localhost への fetch | localhost への WebSocket |
|---|---|---|
| LAN（プライベートなアドレス、http） | 通る（許可も求められない） | 通る |
| 公開サイトとみなした場合（http。Chrome の `--ip-address-space-overrides` で試した） | Chrome が断る | Chrome が断る |

公開サイトの https のページでは、Chrome は断らずに許可を求めるはず（確かめていない）。

### 各エディタの都合

**WebSocket の SHA-1 は替えられない。** 接続を始めるときの応答（`Sec-WebSocket-Accept`）は
WebSocket の決まり（RFC 6455）で SHA-1 と定められ、ブラウザが値を確かめる。本文のハッシュは
こちらで決めたもので、どのエディタにも標準で SHA-256 があるので、そのままにする（設計者は
「sha-1 が面倒なら crc32 でも」とした。SHA-1 は Lua で 60 行ほど書けば済んだ）。

- **Neovim**: `vim.uv`・`vim.base64` は 0.10 から。Ubuntu 26.04 の apt の neovim は 0.11.6（universe）、
  24.04（noble）は 0.9.5（設計者、2026-10-06）。0.9.5 以上を対象にした（クロコの案）
- **VS Code**（1.140、組み込みの Node は v24）: `http` の待ち受けと `upgrade`、`crypto` の SHA-1・
  SHA-256 が使える。WebSocket の待ち受けは組み込みに無い（Node の WebSocket はつなぐ側だけ）。
  `.vsix` は zip で、手作業でビルドしたものを `code --install-extension` でインストールできる。ウィンドウごとに
  拡張機能が動くので、ポートの取り合いは Emacs と同じ引き継ぎで扱う
- **Vim**: 待ち受ける機能が無い（channel はつなぐ側だけ）。Vim 用を作るなら、待ち受ける小さな
  ヘルパープログラムを `job_start` で起動し、それと channel で話す形になる。Ubuntu ではヘルパーを
  python3 で書ける。Windows の Vim でも使うなら、そのときに別の手段を考える（設計者、2026-10-06）。
  Vim 用は作っていない

### 経緯

はじめは GhostText のプロトコルで、atomic-chrome（Emacs）や VS Code の GhostText につないでいた
（設計者の PukiWiki の `remoedit` プラグインの後継）。毎回全文を送り、名前は最初の1回しか使われず、
カーソルを扱うかはエディタ次第だったので、専用のプロトコル（v1）とプラグインに替えた（2026-10-06）。
atomic-chrome では、待ち受けていた Emacs を閉じるとつながらなくなっていた。
