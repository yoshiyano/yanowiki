# ログイン（`#login` プラグイン経由）

#img(ログインのフォーム（/.login）>login-form.png)

IDとパスワードを `/.plugin/login` へ送ると、サーバー側で照合します
（[ページの中でログインする](/Tech/LoginPlugin)）。結果はその場では出さず、フォームを
置いたページ（`back`）へ303で転送してから案内を出します。そのまま出すと、再読み込みで
IDとパスワードが送り直されるためです。打った値は転送先へ持ち回しません。

| | 転送先のクエリ | 出るもの |
|---|---|---|
| 合っていた | `?login=done` | 「ログインしました。」の案内 |
| 違っていた | `?login=ng` | 1秒おいてから、断りの案内 |
| ロック中 | `?login=lock` | ロックされている旨の案内 |

ほかの値（承認待ちの `?login=pending` など）は
[ページの中でログインする](/Tech/LoginPlugin#結果はページのurlで受け取る) にあります。
1秒（`auth.RETRY_DELAY`）待つのはサーバー側です（総当たりの速度を落とすため）。

照合が通ると、ログイン状態をcookieに控え、次からはパスワードが要りません。

| 名前 | 中身 |
|---|---|
| `wikiuser_<Wiki名>` | そのアカウントの `uid`。`#login` のID欄を埋めるのにも使う |
| `wikiauth_<Wiki名>` | そのログイン状態が本物であることの**合言葉**（下記） |

どちらも `Path` はそのWikiのURL（`/=<Wiki名>`。起点Wikiは `/`）・`HttpOnly`・
`SameSite=Lax`・期限2日で、HTTPS で開いたときは `Secure` も付けます（Apache などの後ろでは
`X-Forwarded-Proto` で判断します）。HTTP で開いたときに付けないのは、付けるとブラウザが cookie を
送らず、ログインできなくなるためです。置きかたの決まりは `wikilib.web.set_wiki_cookie` に
まとめてあり、テーマのcookieも同じ関数で置きます。起点Wikiのcookieは `Path=/` でどのWikiにも送られるので、
名前にWiki名を付けて区別しています（`paths.wiki_cookie_name`）。サービス全体の操作をWiki名の無いURLに
限っているのもこのためです（[起点Wikiの役割](/Tech/DesignPolicy/Farm#起点wikiの役割)）。以下では `_<Wiki名>` を
略して `wikiuser`・`wikiauth` と書きます。

## 別のサイトから送られた POST を断る

cookie の `SameSite=Lax` に加えて、書き換えの POST はすべて、`Origin`（無ければ `Referer`）の
ホストとポート番号が、要求の宛先（`Host`、プロキシ越しなら `X-Forwarded-Host` も）と同じときだけ
受けます（設計者の決定、2026-10-23。フォームごとのトークンは使いません）。照合は入口（`wiki.py` の
`dispatch`）の1か所で、本体の画面もプラグインの `_action` も同じように守られます。
`SameSite` では同じサイトとして扱われる、隣のサブドメインからの送信も断れます。

| 送られてきたもの | 扱い |
|---|---|
| `Origin` が同じホスト | 受ける（スキームは比べない。TLS を終えるプロキシの後ろでは食い違うため） |
| `Origin` が別のホスト・`null` | 403「受け付けません」。標準エラー出力に `[csrf]` で残す |
| `Origin` が無く `Referer` がある | `Referer` で同じように比べる |
| どちらも無い | 受ける（ブラウザ以外の curl・スクリプトから。CSRF はブラウザに送らせる攻撃なので） |

表の細部（スキームを比べない・どちらも無ければ受ける・断ったことの残しかた）はクロコの実装例
（設計者は未確認）。仕組みは `wikilib.web.cross_site_reason`、テストは `tests/test_crosssite.py`。

## 合言葉（`wikiauth`）の作りかた

次の材料を連結して SHA-1 にかけた値です（`wikilib.auth.session_token`）。`cnt` だけは
`\x00` を挟んで最後に付けます。

| 材料 | なぜ入れるか |
|---|---|
| `uid` | 誰のものかを分ける |
| Wiki名 | どのWikiのものかを分ける |
| 日付番号 | `time.time() // 1日`。1日ごとに変わる |
| `pw`（保存されているハッシュ値） | パスワードを変えると無効になる |
| 設置ごとの合言葉 | `config/secret.txt` の10文字。画面には出さない |
| `cnt`（`\x00` の後ろ） | ログイン状態の世代。上げると、それまでの合言葉がすべて無効になる。無い・空は0 |

`wikiuser` だけでは何も認めません。`wikiauth` と揃って、サーバー側で作り直した値と
一致したときだけ通ります（`wikilib.auth.current_user`）。`pw` を先頭2文字だけ混ぜる案は、
推測すべき部分が256通りしかなく手元で総当たりできるので採らず、`pw` 全体と設置ごとの
合言葉を混ぜています。

`config/secret.txt` は無ければ自動で作ります（`0600`、紛らわしい字を除いた英数字10文字）。
漏れると一覧のハッシュ値と合わせて合言葉を作られるので、Wikiの外に出さないでください
（gitの追跡からも外してあります）。

## 他端末からの認証を解除する（`cnt`）

`#login` の「アカウント」タブの、「ログアウト」の上にあるボタンです。パスワードは変えずに、
いま出回っている合言葉をすべて無効にします。

1. `passwd.cnt` を1つ上げる（`userdb.bump_cnt`）。それまでの合言葉は端末を問わず通らなくなる
2. 押した端末には、新しい `cnt` で合言葉を作り直して置き直す（`remember_login`）。
   押した端末は入ったまま、他の端末は次に開いたとき入れ直しになる

- 対象は押した人自身のアカウントだけです（`current_user` から決める）
- `cnt` はパスワードのハッシュ（`pw`）には混ぜません（生のパスワードを持たないので、
  混ぜると誰もパスワードで入れなくなる）
- 列はあとから足したもので、古いDBでは自動で足され、既存のアカウントは0です。
  このバージョンに上げた直後は、全員のcookieが1度だけ通らなくなります

## 1日ごとに変わりますが、毎日開いていれば入れ直しは要りません

合言葉は1日で変わりますが、昨日のぶんも通し、ページを開いたときにその場で今日のぶんに
置き換えます（`auth.refresh_login`。`wiki.py` の `dispatch` が応答を返す前に呼ぶ）。毎日開いている人は
入れ直しになりませんが、2日以上あくと切れます。
cookieの期限も2日にしてあるのは、25時間ぶりに開いた人がcookie自体を失わないためです。

#note(type=warn){{
**守れること・守れないこと**

- パスワードを変えれば、持ち出された合言葉は通らなくなります
- パスワードを変えずに取り消せるのは、「他端末からの認証を解除する」を押したときだけです。
  どちらもしなければ、持ち出された合言葉は最長2日通り続けます
- **管理者のログイン状態が1つあれば、そこから全部が開きます**（`/.admin/accounts` から
  他人のパスワードを書き換えられるため）。管理者の合言葉は、パスワードと同じ重さで扱ってください
}}

## 端末ごとのログインの設定

端末ごとに、ログインしたまま何日続けるかと、決まった曜日・時刻に入れ直させるかを決められます
（`#login` のアカウントタブから）。設計者が決めたことは次のとおりです（2026-11-18）。

- 日数は、最後に開いてから N日（開くたびに延ばす）。最大14日
- 曜日・時刻の設定も端末ごと
- 設定していない端末は、上の合言葉のまま（毎日開いていれば続き、2日あくと切れる）
- 設定はログアウトしても端末に残す

設定は `wikilogin_<Wiki名>` の cookie（`<日数>.<曜日>.<時刻>`、期限400日）に置き、ログインのたびに
その設定で合言葉を作ります。以下はクロコの実装例です（設計者は未確認）。

| 部分 | 中身 |
|---|---|
| 形 | `2.<作った時刻>.<曜日・時刻を数えはじめる時刻>.<日数>.<曜日>.<時刻>.<照合値>` |
| 照合値 | 数字の部分すべてと、上の合言葉と同じ材料（`uid`・Wiki名・`pw`・`cnt`）を、`site_secret` を鍵にして HMAC-SHA256 にかけたもの |

- 数字を書き換えると照合値が合わないので、手で日数を延ばせません
- 開くたびに、作った時刻をいまにして作り直します。画像やCSSの要求のたびに置き直さないよう、
  作ってから1時間たったときだけにしています（`REFRESH_AFTER`）
- 持ち出された合言葉も、使われ続ければ延びます。止めるのは、曜日・時刻の入れ直しと、下の取り消しです
- 曜日・時刻は、その時刻を過ぎると、延ばしていても通らなくなります。数えはじめはパスワードを入れた時刻か
  設定した時刻で、延ばしても動きません。設定する前に過ぎた時刻では切りません。時刻はサーバーの時計（地方時）で見ます
- 曜日・時刻だけを決めて日数を決めていないときは、2日（48時間）にします
- 取り消しは上と同じです（他端末からの認証を解除する・パスワードを変える・ログアウト）。
  「他端末からの認証を解除する」を押した端末は、作り直して残します
- 画面に出す「いつまで入っていられるか」は `auth.login_state` の `until` です。延ばすのは画面を描いたあとなので、
  延ばす前の期限（`expires`）ではなく、この要求で延ばしたあとの期限を出します
