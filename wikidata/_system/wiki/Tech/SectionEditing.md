# セクション編集

見出し単位でページの生テキストをその場で編集し、プレビューして保存できます。

サーバー側は `/.section/<ページパス>`（GETで取り出し、POSTで保存。
[保存のやりとり](#保存のやりとり)）、画面側（ダブルクリックの検出・編集欄・保存ボタン）は
テーマの `theme/common.js`（wikiThemes の持ち物）です。

そのページの編集の権限（`W`）が無いと使えません。テーマは権限が無ければ本文に
`data-editable` を付けず、URLを直に呼んでも取り出し・保存とも403になります。

## 使いかた

本文の見出しか段落を **Ctrl+Alt+ダブルクリック** します（トリプルクリックはブラウザの
テキスト選択と紛らわしいため使っていません）。

## 編集範囲の決めかた

- **見出しをクリック**: その見出し（レベルL）から、次のレベルL以下（同じか上位）の見出しの手前まで。配下の下位見出しは含みます。
- **本文をクリック**: 直前の見出しの次の行から、同じ規則で決まる終端まで（見出し行は含みません）。
- **見出しが無い、または最初の見出しより前をクリック**: ページ先頭から最初の見出しの手前まで（無ければページ全体）。タイトルとして抜き出された1行目のh1は含みません。

## 仕組み

- 範囲はブラウザ側でDOM（`.content` の直接の子と、直前の見出し）から決めます。
- `GET /.section/<ページパス>?heading=<見出しid>&scope=header|body` でその範囲の生テキストを取り、textareaに入れます。
- 入力が止まると `POST <ページパス>?cmd=preview` へ送り、返ったHTMLをその場に出します。保存時と同じレンダラ・プラグインを通ります。
- 添付の裸のファイル名（`logo.png` など）も、そのページの添付として解決されます。

サーバー側が頼るのは、断片をparse・renderできることと、見出しの情報（レベル・行位置）
だけです。Markdown（`.md`）もPukiWiki記法（`.txt`）も同じ仕組みで扱えます。

## 別で編集中のときも保存できます

そのページの[一時保存](/Tech/EditGuide/Draft)を預かっているとき、タイトルの脇に
**（編集中）** と出ます（サーバーが `title_note` を渡し、本文に `data-draft` が付く。
見た目は `common.css` の `.page-editing`）。

この印が出ていても保存できます。書きかけを持っている人があとで保存したときに
競合が見つかり、[統合する画面](/Tech/ConflictMerge)で突き合わせられるためです。

ただし「書きかけがあり、しかもセクション編集を開いてから更新もあった」場合は断ります。
統合には統合結果を書きかけとして預ける必要があり、書きかけはページに1つしか
持てないので、その人の書きかけを上書きしてしまうためです。この場合は編集画面から
統合します。

## 既知の制約

- そのページが元から使っていないプラグイン（`#katex()` など）は、資材が読み込まれて
  いないのでプレビューで組版されません（エラーにはならず素のまま出ます。`#code` の
  色分けも同じ）。編集画面は全プラグインの資材を読み込むので、この制約はありません。
- 見出しの `id` は h1〜h6 すべてに振られるので、どの深さでも編集できます
  （[設計方針](/Tech/DesignPolicy#見出しのidはシステムが決める)）。
- ページ全体に依存する構文（`#contents`、PukiWiki記法の注釈 `((…))` など）は、
  節単体のプレビューでは正しく出ないことがあります。
- 同時に開けるのは1つまでです。
- `#viewable_period` などで表示を止めているページでは使えません（取り出し・保存とも403）。
  画面に出ているのは案内文で、選んだ節とサーバーが本文から切り出す節が食い違うためです。
  編集画面からは編集できます。

## 保存のやりとり

**送るのはページ全体です**（Wiki設計者の指示、2026-09-01）。画面は開いた節の前後を
隠し持っておき、編集した節と繋いで送り返します。保存は[編集画面からの保存](/Tech/EditGuide/Save#保存)と
同じ扱いになり、「どの節をどこへ書き戻すか」を保存のときに考えずに済みます。

### 開くとき

`GET /.section/<ページパス>?heading=…&scope=…&parts=1`

```json
{"before": "…", "section": "…", "after": "…", "origin": "…"}
```

3つを繋ぐと元のページに1バイトも違わず戻ります（`split_section_text` が
`splitlines(keepends=True)` で分けるため。`tests/test_section.py` で固定）。`origin` は
ページ全体のハッシュで、競合の判定に使います（編集画面の `origin` と同じもの）。

`parts=1` を付けなければ、その節の生テキストだけを返します。

### 保存するとき

`POST /.section/<ページパス>`

| 送るもの | 中身 |
|---|---|
| `source` | ページ全体（前 ＋ 編集した節 ＋ 後） |
| `origin` | 開いたときに受け取ったハッシュ |

| 返るもの | 意味 |
|---|---|
| `{"ok": true, "changed": true, "url": …}` | 保存した |
| `{"ok": true, "changed": false, …}` | 中身が変わっていなかった |
| `{"ok": false, "conflict": true, "url": …, "message": …}` | 開いてから更新があった。`url`（[統合する画面](/Tech/ConflictMerge)）へ |
| `{"ok": false, "message": …}` | 断った（理由が `message`） |

- 保存はページ全体の保存と同じ後始末（`pagesave.save_page`）を通り、バックアップ・DB・
  平文が揃って更新されます。`&date;` などの[保存時の置換](/Tech/EditGuide/Save#保存)も効きます。
- 書きかけには触りません（別の場所で編集中の人のものなので）。
- 結果が空になる保存は断ります。削除は編集画面から行います。

### 長いページは分けて送れます

1回のPOSTの上限（8MB。日本語はフォーム送信で3倍に膨らむので、実質90万バイトほど）に
届くページは、[編集画面と同じ仕組み](/Tech/EditGuide/ChunkedUpload)で分けて
送ります（`chunk_id` / `chunk_index` / `chunk_total` と `part`）。そろうまでは **204** が返ります。

### ページ全体を送る形で要らなくなったもの

- 見出しidの管理（開いてから保存までにidが変わっても関係ない）
- 画面とサーバーの切り出し範囲の食い違い（前後と繋げば同じページに戻る。見出しの文字が
  記号だけで id が付かない場合など、画面に出る範囲がずれる見た目の問題は残る）
- 貼り戻しの行末の始末

一時保存に上書きされる問題は、一時保存が預けた時点のハッシュ（`.draft.origin`）を持つ
ことで解けています（[別で編集中のときも保存できます](#別で編集中のときも保存できます)）。
