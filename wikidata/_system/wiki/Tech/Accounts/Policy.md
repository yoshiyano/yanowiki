# ユーザ登録の受け入れかた（`account.policy`）

Wikiごとに、ユーザ登録（「アカウント作成」）の受け入れかたを設定で持てます。

    account:
      policy: open      # 既定。open / approval

置き場所は `config/default.example.yaml`（共通の既定）と `wikidata/<Wiki名>/config/default.yaml`
で、設定画面（[/.admin/configwiki](/Tech/ConfigWiki)）の「アカウント」タブからも変えられます。
書き損じ・知らない値は `open` として扱います。

決めるのは登録だけです。誰が何を読めて書けるかは、ページごとの権限（`config/privileges`）が
決めます。

| 値 | ユーザ登録 |
|---|---|
| `open`（既定） | 誰でもアカウントを作れ、作れたらそのまま入る |
| `approval` | 誰でも申請できるが、助手か管理者が承認するまで使えない |

管理者だけが作る `closed` は、Wiki設計者の指示（2026-09-21）で外しました。

## 承認制（`approval`）の動き

- 「アカウント作成」で作られたアカウントは承認待ち（`approved = 0`）で始まり、入れません
  （cookieを置かず、`?login=applied`）
- 承認待ちのアカウントでログインすると、パスワードが合っていても `?login=pending` です。
  パスワードが合わないときはふつうの `ng` のままです（承認待ちかどうかを教えないため）
- 権限の上では未ログインと同じで、`g:all` にも入らず、`current_user` も返しません
- 承認待ちがあると、管理者と助手の `#login` の表示に、赤字で「承認待ち x人」が出ます
  （押すと承認する画面へ）
- 承認は `/.admin/approvals`（管理者と助手）。「承認する」で使えるようになり、「断る」で
  アカウントを消します。扱うのは承認待ちのアカウントだけです（承認済みを消せると、助手が
  管理者専用の一覧を通り越せてしまうため）
- 承認済みのアカウントの承認を取り消す画面は持ちません。止めるときは、管理者が一覧で消すかロックします。
  助手が誤って承認したものは、[助手の操作の記録](/Tech/StaffLog)の「元に戻す」で承認待ちに戻せます
  （承認待ちに戻ると、その場で持ち出されたcookieも効かなくなります）
- 管理者が `/.admin/accounts` や `./wiki.py initusers` で作るアカウントは、常に承認済みです

### 申請の受付の限り

誰でも送れる申請で、承認の画面が埋まらないよう、受付に限りがあります（`auth.do_signup`・`userdb`）。

| 限り | 超えたとき |
|---|---|
| 同じ IP からは1時間に3件まで（`auth.SIGNUP_MAX`。受け付けた申請だけを数える） | 受け付けず `?login=busy` |
| 承認待ちの申請が20件あるあいだは受け付けない（`userdb.PENDING_MAX`） | 受け付けず `?login=closed`。承認の画面と、承認できる人が開くページのタイトル右端の info（`pagenotice.signup_notice`）に「受付を止めています」 |
| 申請から3日たっても承認されなければ、断ったときと同じく消す（`userdb.PENDING_DAYS`） | ID も空く。消えた ID でログインすると、ふつうの `ng` |
| 表示名は32文字まで（`userdb.NAME_MAX`。管理者が作る・直すときも同じ） | 受け付けず `ng` |

- 申請した日時は `applied_at`。期限切れは、承認待ちの一覧を引くとき（承認の画面・`#login` の「承認待ち x人」・申請）と、ログインの照合の前に片付けます
- 承認を取り消して承認待ちに戻ったアカウント（`applied_at` が 0）は、申請ではないので上限に数えず、期限でも消しません。助手の承認・断りを「元に戻す」したときは申請に戻ったものとして、その時点から3日を数え直します
- 同じ IP の回数は、一時フォルダの `wikisystem-signup-<設置場所の要約>.json` に直近1時間ぶんを記録します（`/.updatePageAuth` の回数と同じ作り）

## 何のための設定か

ログインしていれば編集できる扱いは、もともと誰が編集したかを記録するためのもので、
誰でも使えるWikiが前提でした。読み書きできる人を制限したいWikiのために、制限は
ページごとの権限が受け持ち、Wikiを作るときに権限の既定値（`*` の行）として与えます。
ユーザ登録の側は `account.policy` で持ちます。

## 想定している5つの使いかた

Wiki設計者が挙げた利用形態です。これを「権限の既定値」と `account.policy` の組で表します。

1. 自分だけで使う。ユーザ管理の概念がない
2. LAN内で、信頼できる人だけが、ログインなしで自由に書き換える。一部のページだけ
   閲覧・編集を制限する
3. LAN内で、書き換える人が複数。誰の文責かを明確にするため、ログインした人だけ
   編集できる。一部のページは閲覧・編集を制限する。アカウント追加は参加者が自由にできる
4. 基本的に外部公開。3と同じ使いかただが、アカウント追加は staff の承認が要る
5. 閲覧にもログインが要る。書き込みは特定のユーザだけ。ユーザ登録には staff の承認が要る

`approval` は4と5で有効にします。Wikiを作るときにこの使いかたを選びます
（[新しいWikiを作る仕組み](/Tech/NewWiki) の「利用形態を選ぶ」）。
