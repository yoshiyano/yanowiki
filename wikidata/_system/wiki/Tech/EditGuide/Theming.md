# テーマを使わない編集画面

編集画面がテーマから独立していることと、その資材の持ちかたです。

## テーマを使わない独立したページ

**編集画面はテーマを使いません。** ページ全体を編集機能が自分で組み立てます。

以前はテーマの本文領域に埋め込んでいましたが、テーマが決めた本文幅
（`--content-max` など）に閉じ込められ、**広い画面でも入力欄とプレビューが
細いまま**でした。書く場所と読む場所では求められる形が違う、というのが
分けた理由です。

**ヘッダ**（サイト名・対象ページ・「ページを見る」）の下に、2つの領域が並びます。

| | |
|---|---|
| ページ一覧 | 編集の枠（タブ・入力欄・プレビュー…） |

画面の高さいっぱいを使い、入力欄・プレビュー・差分・オリジナルが**余った高さを
分け合って伸びます**。テーマを差し替えても・一から書いたテーマでも、編集画面は
いつも同じ形と操作感になります。

### 中身だけはテーマに任せる

枠組みは編集機能のものですが、**プレビューとオリジナルの中身はテーマが描きます。**
「保存したらこう見える」を確かめる場所なので、そこが本物と違う見た目では
確かめる意味が薄いためです。両方に `content` クラスを付けてあるので、
テーマが本文向けに書いた指定（見出しの罫線・表・引用など）がそのまま効きます。

読み込む順は次のとおりで、**枠組みの指定が最後に勝ちます。**

```
プラグインのCSS → テーマのCSS → /.editor.css
```

テーマのCSSが本文以外に効かせているのは `body` `a` `mark` くらいなので、
枠組みが崩れることはありません。`body` の余白だけは全画面にするために
打ち消しています（字づかいはテーマのものをそのまま使います。
プレビューの中だけ別の字にしても、見え方を確かめられないためです）。

#note(type=warn){{
`hidden` 属性を使って表示を切り替えているので、こちらから `display` を与えると
**隠す指定に勝ってしまいます。** 実際、切り替えていないほうのビューが高さを
半分持っていきました。`[hidden]` を優先させる指定を1行入れてあります。
}}

## テーマに依存しない作り

編集画面は[テーマを使わない独立したページ](#テーマを使わない独立したページ)です。
**見た目と動きに必要な資材は、編集機能自身が持っています。**

| 資材 | URL | 実体 |
|---|---|---|
| スタイル | `/.editor.css` | `_sys/editor/editor.css` |
| スクリプト | `/.editor.js` | `_sys/editor/editor.js` |

テーマの `theme/` には置いていません。編集は「ページの見た目を整える場」ではなく道具なので、
**どのテーマを選んでいても同じ操作感で使えるべき**だと考えたためです。
テーマが編集画面用のCSSを用意していなくても崩れませんし、テーマを壊してしまったときでも
編集画面から直せます。メニュー・検索といったテーマの枠組みは、編集画面には出ません
（プレビューとオリジナルの中身だけをテーマが描きます）。

CSSは色をテーマのカスタムプロパティ（`--bg`、`--accent` など）から受け取り、
無ければ既定値を使います。そのためテーマに馴染みつつ、単独でも成立します。

```css
.page-editor {
  --e-accent: var(--accent, #0969da);
}
```
