# ページ選択ダイアログ（TreeView）

`<dialog>` を使ったページ一覧の木構造です。木そのものは**共通のTreeView**
（`_sys/treeview/`、`WikiTreeView`）が作り、添付ファイルの移動先を選ぶこの
ダイアログのほか、[サイドバーのページ一覧](/Tech/EditGuide/Sidebar)でも
同じ実装を使い回しています
（詳しくは [ページ一覧のTreeView](/Tech/Reference/Views#ページ一覧のtreeview)）。

ページ一覧は `/.pagetree` からJSONで取ります。**編集画面を出すたびに全ページを
走査せずに済むよう、ダイアログを開いたときに初めて取りに行き、一度読んだら覚えておきます。**

```json
{ "name": "", "kind": "dir", "pagepath": "", "subpath": "", "has_file": true,
  "draft": false, "title": "トップ",
  "children": [
    { "name": "index", "kind": "page", "pagepath": "", "subpath": "index",
      "has_file": true, "ext": ".md", "draft": false, "children": [], "title": "トップ" },
    { "name": "Tech", "kind": "dir", "pagepath": "Tech", "subpath": "Tech",
      "has_file": true, "draft": false, "title": "技術ドキュメント", "children": [
        { "name": "index", "kind": "page", "pagepath": "Tech",
          "subpath": "Tech/index", "has_file": true, "ext": ".md", "draft": false,
          "children": [], "title": "技術ドキュメント" }
      ] }
  ] }
```

**木は実体のファイル構成そのままで、フォルダの中の `index` も1つの項目として
木のデータには含まれます。** 添付ファイルの置き場所は実体のパス（`subpath`）で
決まるため、`/Tech` が `Tech/index` を指していることを木自体は常に持っています。
**画面に出すかどうかは `showIndex` オプションで決まります**（`index` を独立
した行にせず、フォルダの行がその入口を兼ねる既定と、独立させる場合の両方を
選べます）。

| 種別（`kind`） | 扱い |
|---|---|
| `dir` | 階層そのもの。クリックすると開閉します。`showIndex` が偽なら中の `index` を兼ねて**選べます**（フォルダ相当のページを選ぶのと同じ意味） |
| `page` | ページ。選べます。`has_file` が `false` なら平文ファイルはまだありません |

- **名前は `wiki/` の中身をそのまま読んで採ります。** ページパスから組み立て直すと、
  大文字小文字が実ファイルとずれるおそれがあるためです。
  `index.md` と `Index.md` は別のページとして、それぞれの名前で並びます
- 同じ名前の `.txt` と `.md` は1つの項目にまとめます（閲覧時も `.txt` が優先されるだけなので）
- ページを1つも持たないフォルダも、中に下位のページがあれば階層として出します。`index` が
  独立した行として出る設定なら、そこにも `index` を出すので「先に添付だけ置いておく」ができます
- **中身の何も無いフォルダは出しません**（ページも下位のフォルダも無く、入口の `index` に添付も
  無いもの）。表示から外すだけで、フォルダを消すのは[取り込み](/Tech/PageDataBase/Writes#空のフォルダを片付ける)です
- `draft` は一時保存を預かっているかどうか。サイドバーのページ一覧だけが使います
- `ext` はページ（`kind` が `page`）の拡張子（`.txt` / `.md`）です
- フォルダの `title` は、その入口ページ（`index`）の見出しです
- 各行には**実体のパス**（`subpath`）を添えます。使う側はこれを見て、
  実在するか（`has_file`）などを判断できます

並び順は、そのフォルダ自身のページ（`index`）→ フォルダ → ページの順で、
いずれも**大小文字を無視した名前順**です。素の名前順だと大文字で始まる名前が
すべて先に来てしまい（`UsageGuide` より `mainmenu` が後ろ）、目で追いにくくなります。
フォルダとページが混ざるのも構造が読み取りにくいため、群に分けています。

操作は、折りたたみ（▾/▸）、ページ名での絞り込み、クリックでの選択です。
絞り込みは実体のパスで照合します。
絞り込みは**まず自分自身が一致しないものを隠し、そのうえで一致した子孫を持つ親だけを戻します。**
順番を逆にすると、まだ何も隠れていない時点で親を判定してしまい、全部残ってしまいます。
