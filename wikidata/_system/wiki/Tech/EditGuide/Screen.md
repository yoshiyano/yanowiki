# 編集画面の構成

編集画面のタブ・ボタン・プレビューの組み立てです。

## タブ構成

編集画面は4つのタブに分かれています。どれも**同じページ**を対象にします。

| タブ | 内容 |
|---|---|
| 編集画面 | 本文の入力とそのプレビュー |
| 更新状況 | 左に差分、右に**保存されている内容**を並べる |
| 添付ファイル | そのページの添付ファイルの一覧・追加・削除 |
| 履歴 | そのページの**変更履歴**（バックアップ）。時点を選んで戻せる |

**本文を書きながら差分を確かめる・画像を足す、という行き来が多いため、
別ページに分けていません。** 「編集画面」「更新状況」は同じフォームの中で
見せかただけを入れ替えています（別ページに分けると、書きかけを持ったまま
行き来できなくなるため）。「添付ファイル」「履歴」は仕組みが別の独立した
セクションですが、見た目・操作感は同じタブとして揃えてあります。

`?tab=diff` / `?tab=attach` / `?tab=history` を付けると、そのタブを開いた状態で
表示されます。タブを切り替えるとURLにも反映されるので、再読み込みしても
同じタブが開きます。

### 履歴のタブ

いま編集しているページの変更履歴を見て、選んだ時点へ戻せます。

- **ページの選択は、サイドバーのページ一覧**（編集画面の共通の一覧）で行います。
  履歴タブのまま別のページを選ぶと、そのページの編集画面へ、履歴タブを開いた状態で移ります
- **履歴の一覧は、そのページ一覧の下に出ます**（履歴タブを開いているときだけ）。
  並ぶのは保存の日時と増減の行数で、開いた直後はいちばん新しい時点が選ばれています
- **差分と復元（すべて戻す／部分的に戻す）は、[変更履歴の画面](/Tech/BackupUI)を
  `<iframe>` で埋め込んでいます**。ページ自身のURLへ `?cmd=history` を、`<iframe>` を宛先に
  したフォームでPOSTして開きます（GETでは閲覧の画面になるため）。一覧で選んだ時点は、
  `postMessage`（`wiki-backup-select`）で埋め込みの画面へ知らせます
- **履歴が無いページは、「変更履歴はありません」とだけ出ます**（埋め込みの画面は開きません）
- **タブを開くまで読み込みません。** 編集を始めるたびに履歴の取得を走らせないためです
  （最初に開かれたときに `?cmd=history` へ `data=history` をPOSTして履歴を読み、`<iframe>` を開きます）
- 履歴の削除はありません（取り返しが付かず、編集の途中で触る操作ではないため）
- **履歴から戻すと、ページの保存内容が変わる**ので、この編集画面は古くなります。
  埋め込みの画面が復元の完了を親へ知らせ（`postMessage` の `wiki-backup-restored`。
  同じ出所の、履歴タブの `<iframe>` からのものだけを受けます）、編集画面は
  **書きかけを預けてから開き直します**（預けられなければ開き直しません）。
  開き直した画面は書きかけを出し、そのまま保存すれば**競合として統合の画面**へ進みます
  （復元より前の内容を元に書いていたため）

この形は2度の見直しを経ています。はじめは（Wiki設計者の指示、2026-09-19）バックアップ
管理画面を丸ごと埋め込み、一覧も埋め込みの中にありました。2026-09-24に、ページの
選択を編集画面のサイドバーのページ一覧と共通にし、埋め込むのは差分・復元だけに
改めました（Wiki設計者の指示）。

## ボタンの並び

「編集画面」「更新状況」タブの下に、次の4つが並びます。

| ボタン | 動き |
|---|---|
| 保存 | 本保存する。書きかけは役目を終えるので消える |
| 一時中断（ESC） | いまの内容を書きかけとして預け、閲覧画面へ戻る。**続きをあとで書ける** |
| 内容破棄 | 預かっている書きかけを消して、閲覧画面へ戻る。**取り消せないので確認します** |
| ファイル一覧 | 別のタブでファイル一覧（`/.files/`）を開く。名前の変更・移動・削除はここから（保存はしない） |

**「一時中断」と「内容破棄」は似て見えて逆の動きです。** どちらも編集画面を
離れて閲覧画面へ戻る点は同じですが、一時中断は書きかけを**残し**、内容破棄は
書きかけを**消し**ます。

内容破棄は取り消せない操作なので、ボタンの色を 警告色 にしてあります。

## プレビュー

入力を止めてしばらくすると、そのページの通常URLへ `?cmd=preview` を付けて本文を送り、
HTMLを受け取ります（2026-09-17に `/.preview/<ページパス>` から移しました）。**保存時と同じレンダラ・同じプラグインを通る**ので、
プレビューと保存結果が食い違いません（[セクション編集](/Tech/SectionEditing) と同じ仕組みです）。

まだ保存していない新規ページでもプレビューできます。

## 外部エディタとの連携

textarea を唯一の正として扱う作りにしてあります。GhostText のように
**`input` イベントを発火させずに `value` を直接書き換えるツール**でも
プレビューが取り残されないよう、値の変化を控えめな間隔（0.5秒）で見ています。

外部から書き換えられた内容も、そのまま保存できます。
