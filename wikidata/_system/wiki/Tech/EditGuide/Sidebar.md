# サイドバーのページ一覧

使いかたは [編集する](/UsageGuide/Edit/Page#ページ一覧) にあります。このページは仕組みの説明です。

編集中は、サイドバーにメニューではなく**ページ一覧**が出ます。
編集は行き来の多い作業なので、次に開くページをその場で選べるようにしています。

中身の組み立ては、[ページ選択ダイアログ](/Tech/EditGuide/TreeView)と同じ
共通のTreeView（`_sys/treeview/`、`WikiTreeView`）に任せています。添付ファイルの
移動先を選ぶダイアログと、木の作りかた・
開閉・キーボードでの操作がここでも揃います。フォルダの階層による字下げも
同じ見た目です。

**トップページ（`/`）だけは特別に `(TopPage)` という行を先頭に出します。**
他のフォルダは自分の行が中の `index` を兼ねますが、木のいちばん外側
（ルート）には行そのものが無く、この仕組みに乗れないためです
（`wikilib.pagetree.with_top_page_row`）。ヘッダに出すページ名も、トップ
ページを開いているときは同じ `(TopPage)` にそろえています。

行の名前は、**ファイル名かタイトルのどちらか一方**を出します（並べて出すと
幅の狭いサイドバーを圧迫するため）。出していないほうは行のホバーで確かめられます。
タイトルの無いページは、タイトルを出す設定でもファイル名のままです。
どちらを出すかは[下](#名前の切り替えと並び順)のとおりです。長い名前は
末尾を「…」に打ち切ります。打ち切る幅は設定（`config/default.example.yaml`、
Wikiごとの上書きは `wikidata/<Wiki名>/config/default.yaml`）の
`edit.title_length`（既定24）で決まり、**全角文字は2文字ぶんとして数えます**
（半角換算の幅。例えば半角12文字＋全角6文字で24）。

**「ファイル一覧」は別のタブを開くリンクです**
中身は `<a>`（押すと別のタブを開く）のままで、見た目だけを
一時中断・内容破棄と同じ枠線のボタンにそろえています。保存と同じ強さ（塗り）に
はしていません。

**サイドバーとの境目をドラッグすると幅を変えられます。** 選んだ幅は
`localStorage` に控えておくので、次にページを開いたとき（編集画面は
開くたびに丸ごと作り直されます）も同じ幅で始まります。

## 名前の切り替えと並び順

一覧の上の帯（自動・ファイル名・タイトル）で、出す名前を切り替えます。

| 帯 | 出す名前 |
|---|---|
| 自動 | ページの書きかたごとの設定（`markdown.listname`・`pukiwiki.listname`）。初めの設定では Markdown がタイトル、PukiWiki記法がファイル名 |
| ファイル名 | すべての行をファイル名にそろえる |
| タイトル | すべての行をタイトルにそろえる |

**並びも、出している名前の順に直します。** サーバーが渡す木は常にファイル名順
（`pagetree.sort_key`）のままで、並べ替えはブラウザ（共通のTreeViewの `sortByLabel`）が
描くたびに行います。比べかたはファイル名順と同じ（大小文字を無視した文字コード順。
そのフォルダ自身の `index` → フォルダ → ページの群の順は変えない）で、名前が同じときは
ファイル名で決めます。`(TopPage)` の行（`pinned`）は常に先頭に置きます。

Wiki設計者の指示（2026-10-08）「編集画面の一覧でファイル名とタイトル名を切り替えられるように。またソートもそれぞれの基準で適用するようにしてください。」

クロコの実装例（設計者は未確認）:

- 切り替えを、ファイル名・タイトルに「自動」を足した3つにした。2つだけにすると、書きかたごとの `listname`（2026-09-18の指示）が一覧で効かなくなるため
- 選んだものは `localStorage`（`wiki-edit-list-name`）に控える。幅と同じ流儀（編集画面は開くたびに作り直されるため）
- 切り替えたときは一覧を描き直す。開いていたフォルダは開いたまま、いま編集しているページの行を真ん中へ置き直す
- 帯はサイドバーの上端に貼り付ける（`position: sticky`）。開いた直後は編集中の行を真ん中へ置くためにサイドバー全体がスクロールし、貼り付けないと帯が隠れて見つからない
- 日本語は文字コード順（かなが漢字より先）で、読みの順（五十音）にはしていない
- 並べ替えに使うタイトルは、サーバーが階層の深さに応じて詰めたもの（最短10文字）。同じ書き出しが長く続くタイトルどうしは、末尾の違いを見ない

## 狭い画面では、出し入れする（2026-09-06）

画面が狭い（`60rem` 以下）と、枠は横に並べられず縦に積まれます。そのままだと
**ページ一覧が本文の上に居座り、書く場所へ着くまで毎回スクロールが要ります。**

そこで狭いときは、一覧を**流れから外して画面の左に重ね**、既定では閉じておきます。
出し入れは**左上に固定したボタン**（三本線）で行います。固定してあるので、
下までスクロールしても押せます。

| 操作 | 動き |
|---|---|
| 左上のボタン | 開く・閉じる |
| 一覧の外（暗い幕）を押す | 閉じる |
| 一覧の行を押す | 閉じる（そのページへ移ります） |
| 開閉の三角（`▸`）を押す | 閉じない（階層を開くだけなので） |
| `Esc` | 閉じる |

`Esc` は**一時中断**にも割り当ててあります。一覧を開いているときは一覧が先に
受け止め、`preventDefault()` でそのことを知らせます。中断の側はそれを見て
引き下がるので、**一覧を閉じたつもりが編集も中断される**ことはありません。

広い画面では、この開閉の指定はCSSに存在しません。開いた印
（`.edit-layout.is-side-open`）が付いたまま広げても何も起きないので、
画面幅が変わったときの後始末は要りません。

印は2つあります。

| 印 | 意味 |
|---|---|
| 選択状態（塗りつぶし。TreeView標準） | いま編集しているページ |
| **赤い太字** | 一時保存を預かっているページ |

まだ実体の無いページ（フォルダの `index` など）は、TreeView標準の見た目
（灰色・斜体）でそのまま表せるので、こちらに特別な指定はしていません。

**クリックでの移動と、矢印キーでの選択は別に扱います。** TreeViewの「選ぶ」
（`onSelect`）は矢印キーでの移動でも呼ばれるため、そちらへ繋ぐと矢印を押した
だけでページを離れてしまいます。クリックとEnterキーだけを「決定」として受け、
移動先へ遷移します。**ただしEnterで選んでいるのがいま編集しているページ
そのものなら、同じページへ移り直す意味が無いので本文欄へフォーカスするだけに
します。** Tabキーは、一覧を出て本文へ進む決定として常に本文欄へ進みます
（Shift+Tabでの逆方向はそのままです）。これらはサイドバー側だけの動きで、
共通のTreeView本体は変えていないため、ページ選択ダイアログなど他の場所には
影響しません。

開いた直後は、いま編集しているページの行に自動でフォーカスが当たり、
そのまま矢印キーで一覧をたどれます。**その行は一覧の真ん中に置きます**
（Wiki設計者の指示、2026-09-06）。

共通のTreeViewは選んだ行を `scrollIntoView({block:"nearest"})` で見えるところへ
出しますが、`nearest` は「いちばん動かさずに済む位置」なので、下のほうにある行は
**いちばん下に貼り付いた状態**で止まります。前後がまったく見えず、一覧の中で
いまどのあたりを開いているのか分かりません。

**TreeView側の `nearest` は変えていません。** あちらは矢印キーで1行ずつ動かす
ときの動きでもあり、押すたびに真ん中へ跳ぶと目で追えなくなります。開いた直後の
1回だけ、編集画面の側で置き直しています。上端・下端に近い行は、そこで止まります
（それ以上ずらす先が無いため）。

位置は `getBoundingClientRect` の差で測っています。`offsetTop` は「いちばん近い
`position` 付きの祖先」からの距離なので、囲みの作りが変わると黙ってずれます。

**一覧の組み立てにはJavaScriptが要ります。** 木のデータは編集画面のHTMLに
直接埋め込まれていて（別途 `/.pagetree` を取りに行くことはしません）、
`editor.js` が読み込み時にTreeViewで描きます。無効な環境では「読み込み中…」
のまま止まります。
