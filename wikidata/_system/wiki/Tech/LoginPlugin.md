# ページの中でログインする（`#login` プラグインを支えるシステム側の処理）

ページに置いたフォームから、ログイン・ログアウト・パスワード変更・アカウント作成を
できるようにする仕組みです。画面はプラグイン（`plugin/login.py`）が作り、cookieとDBの
書き換えはシステム側が受け持ちます。このページはシステム側の説明で、記法・表示は
[login](/Syntax/Plugin/login) にあります。

## 送り先

ログイン・ログアウト・アカウント作成は `POST /=<Wiki名>/.plugin/login` へ、`cmd` で用を
分けて送ります（パスワード変更だけは `/.passwd`）。[`/.login`](#ログインの入口-login) の
フォームも同じURLへ送ります。

| `cmd` | すること | 送る値 |
|---|---|---|
| （無し） | ログイン | `uid` `pw` |
| `logout` | ログアウト（cookieを捨てる） | — |
| `revoke` | 他端末の認証を解除する（`cnt` を上げ、押した端末だけ合言葉を作り直して残す） | — |
| `signup` | アカウントを作って、そのまま入る（承認制のWikiでは承認待ちで作られ、入れない） | `uid` `name` `pw` `pw2` |

`/.passwd` へ送る値は `uid` `current` `new1` `new2` です。

## `back` に**そのページのパス**を入れる

`back` があると、済んだあとそのページへ戻します。ルートページなら空文字（`value=""`）で、
「送っていない」とは区別します。

```html
<input type="hidden" name="back" value="Tech/LoginPlugin">
```

#note{{
**受け取るのはページパスだけで、URLはシステム側が組み立てます**（好きなURLへ飛ばす
踏み台にしないため）。`/` で始まる値・`:` を含む値・システムのURL（`.` や `=` で始まる
名前）は、`back` が無かったものとしてそのWikiの `/` へ戻します。例外は `.login` だけです。
}}

## 結果はページのURLで受け取る

戻り先には `?login=…` が付きます。プラグインはこれを見て文言を出します。

| 値 | 意味 |
|---|---|
| `done` | 入れた（パスワード変更もこれ） |
| `made` | アカウントを作って入った |
| `applied` | アカウントを申請した（承認制のWikiで承認待ち。入れない） |
| `pending` | 承認待ちのアカウントでログインしようとした（入れない） |
| `out` | 出た |
| `revoked` | 他の端末のログイン状態を取り消した（押した端末は入ったまま） |
| `ng` | 通らなかった |
| `lock` | ロックされている（管理者に解除を頼む） |

`ng` のときは `&left=n` が付くことがあります（ロックが近いことの断り）。文言は
`wikilib.auth.lock_warning(left)` で作ります。`1` なら「（次回失敗したらロックします）」、
`2`〜`4`（`authlog.WARN_LEFT` まで）なら「（ロックまで残りn回）」、それ以外は空文字です。
同じ文言をプラグイン側に書かないでください（決まりは
[アカウントの仕組み](/Tech/Accounts/AuthLog#ロックが近いことの断り)）。

`?login=…` と `&left=…` は、`_convert` の中で `bottle.request.query` から読みます。

## いま誰が入っているか

`wikilib.auth.current_user(context.wiki_dir, context.farm)` が、入っていればアカウント
（`uid` / `name` などの辞書）、いなければ `None` を返します。

## アカウント作成は誰でもできます

`cmd=signup` は誰でも通ります。作ったアカウントをすぐ使えるかは、設定 `account.policy`
（ユーザ登録の受け入れかた）で決まります。

| `account.policy` | 作ったアカウント |
|---|---|
| `open`（既定） | そのまま入れる（`?login=made`） |
| `approval` | 承認待ちで作られ、助手か管理者が `/.admin/approvals` で承認するまで入れない（`?login=applied`） |

詳しくは [アカウントの仕組み](/Tech/Accounts) の「ユーザ登録の受け入れかた」にあります。

#note(type=warn){{
**`open` のWikiでは、登録ユーザ全員（`g:all`）に編集を許したページは、アカウントを
1つ作れば誰でも編集できます**（[ページごとの権限](/Tech/PagePermissions)）。
}}

## `/.plugin/login` を受ける `_action`

`POST /.plugin/login` は、他のプラグインの `_action`（`/.plugin/ls` など）と同じく
`wikilib.plugins.render_plugin_action` が振り分けます。`plugin/login.py` の
`_action(context)` は、`wikilib.auth` の `back_page_url`/`do_login`/`do_logout`/
`do_revoke_others`/`do_signup` を呼ぶだけです。

これらの関数は `(config, farm, wiki_dir, explicit_farm)` を引数に取るので、
`PluginContext` に `explicit_farm` を持たせてあります。

## プラグイン記法・表示

```
&login();      いま入っている人の表示名（入っていなければ「来訪者」）
&login(id);    いま入っている人のID（入っていなければ「未登録」）

#login()       入っていないとき  … ログインフォーム
                                   （タブを切り替えてアカウント作成も）
               入っているとき    … パスワード変更フォームと、「他端末からの認証を解除する」
                                   「ログアウト」のボタン（アカウントのタブ）
               管理者・助手      … さらに「管理者メニュー」のタブが増える。承認待ちの
                                   アカウントがあれば、ログイン中のユーザーのすぐ下に
                                   赤字で「承認待ち x人」（押すと承認する画面へ）

#login(){案内文}   案内文をフォームの上に添える（省略できる）
```

ブロックのほうは括弧が要ります（`#login` だけでは文字のまま出ます）。

- ログイン中の「アカウント」タブは、いまログインしているユーザー（表示名とID）を示します
- 送信後の案内（`div.login-notice`）は、タブ（`div.login-tabs`）の下に出します
- ログインのページは編集者が自由に用意できますが、ナビの「ログイン」リンクが指す先は
  `/.login` です（次節）

## ログインの入口 `/.login`

ヘッダの「ログイン」リンクは **`/.login`** を指します（Wiki設計者の指示、2026-09-21）。
中身は `#login()` と同じフォームです（`wikilib.views.render_login`）。

- システムのURLなので、ページ名と衝突せず、ページごとの権限の対象にもなりません。
  閲覧にもログインを求めるWiki（`*:R:g:all`）でも開きます
- `?back=<ページ>` を付けると、ログイン・登録できたあとにそのページへ戻ります。
  戻り先は隠し欄 `next` で運び、`back` と同じ確かめを通します。閲覧を断る403の画面
  （未ログイン向け）と編集を断る画面に、このリンクが出ます
- 失敗（`ng`・`lock`）・出た（`out`）・承認待ち（`applied`・`pending`）は `/.login` に戻して
  知らせ、成功（`done`・`made`）のときだけ `next` のページ（無ければそのWikiの `/`）へ移ります
- ナビの「ログイン」は、いま開いているページを `?back=` として持ちます（トップとシステムの
  画面には付けません。`themes.login_href`）
- ナビのリンク先はテーマのコンテキスト変数 `login_url` で、全テーマ共通のメニュー
  `common_menu`（`themes.common_menu_html`）にも同じリンクが入ります

以前はナビのリンクを `Login` というページへ向けていましたが、閲覧にログインを求める
Wikiではそのページが権限で読めなくなる、実在の `Login` ページがその役を奪う、という
問題があったので、システムのURLへ移しました。`Login` はいまはふつうのページ名です。

## 「管理者メニュー」のタブ

ログイン中の相手が管理者か助手なら、タブが1枚増えて `/.admin` と同じ道具の一覧が
出ます。一般のアカウントにはHTMLにも出しません。

| 何を | どこが |
|---|---|
| 管理者か助手か | `wikilib.auth.is_staff`（`admin` か `g:staff`） |
| 道具の一覧（中身のHTML） | `wikilib.adminui.admin_tools_html` |

同じ一覧を2か所で組み立てないよう、道具は `adminui.TOOLS` に1行書けば `/.admin` と
このタブの両方に出ます。見た目（`acct-` のクラス）は `/.admin` 側のCSSにあってふつうの
ページには届かないので、最低限の体裁を `plugin/login.css` に置いています。
