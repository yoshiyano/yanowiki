# 記録の形とパスワードの持ちかた

アカウントの記録の形と、パスワードの持ちかた（とその弱さ）です。

## 記録の形

置き場所はWikiごとの `wikidata/<Wiki名>/config/users.db`（SQLite）で、全Wiki共通の
アカウントは持ちません。

```sql
CREATE TABLE passwd (
    uidnum INTEGER PRIMARY KEY,   -- 内部の番号
    uid    TEXT NOT NULL,         -- ログインに使う名前（#loginプラグインで入れるほう）
    pw     TEXT NOT NULL,         -- パスワードのハッシュ値
    name   TEXT NOT NULL,         -- 画面に出す名前
    approved INTEGER NOT NULL DEFAULT 1, -- 承認済みか（0は承認待ち）
    cnt    INTEGER NOT NULL DEFAULT 0     -- ログイン状態の世代（上げると合言葉が全部無効になる）
);
```

`approved` と `cnt` はあとから足した列で、古いDBを開いたときに自動で足されます
（既存のアカウントは承認済み・0）。

番号1に `admin` と `管理者` が入ります。最初のパスワードは作る人が決めます（`/.newwiki` では
必須の入力欄、`./wiki.py initusers` では実行時に聞く）。`userdb.create_db` をパスワードなしで
呼んだときだけ既定の `adminpw` になりますが、画面とコマンドはどちらも空のパスワードでは
作りません。

### いつ作るか

**画面を開いても作りません**（Wiki設計者の指示、2026-09-05）。作るのは次の2つだけです。

| きっかけ | どこが |
|---|---|
| `/.newwiki` で新しいWikiを作ったとき | `wikilib.newwiki.create_wiki` |
| `./wiki.py initusers =<Wiki名>` を実行したとき | `run_initusers`（既にあるWiki向け） |

```bash
./wiki.py initusers =sandbox
#   [sandbox] 管理者の最初のパスワード:     （打った文字は出ません）
#   もう一度:
#   [sandbox] アカウントの記録を用意しました（admin / 入力されたパスワード）。
```

すでにあれば何もしません。Wikiを省略すると、いまいる場所か既定のWikiが対象です
（`updatepage` と同じ決めかた）。

以前は画面に触れた時点で作っていたので、見ず知らずの相手のアクセスで、既定のパスワードを
持つ管理者アカウントがWikiに生えていました。記録が無いWikiでは、照合は必ず失敗し、一覧は
作りかたの案内だけを出します。

### IDに使える文字

半角の英数字だけです（`[0-9A-Za-z]`、64文字まで）。環境によって入りかたが変わる文字
（全角と半角、日本語入力）で「入れたつもりで入らない」事故を防ぐためです。判定は
`wikilib.userdb.check_uid()` の1か所で、入力欄の `pattern` 属性は補助です。

### 番号（uidnum）の決めかた

いま残っている行の最大値 + 1 です（管理用の表は持ちません）。途中の番号は埋めませんが、
いちばん大きい番号を消すと、その番号は次に足した人に回ります。

```
1, 2, 3 が居る → 2 を消す → 次は 4（2 は空いたまま）
1, 2, 3 が居る → 3 を消す → 次は 3（同じ番号が回る）
```

記録の側からアカウントを指すときは、番号ではなく `uid` を使ってください。

## パスワードの持ちかたと、その弱さ

生のパスワードは持ちません。`account.pw_salt`・`uid`・パスワードを `\x00` を挟んで連結し、
SHA-1 にかけた値を `pw` に入れます。

    pw = SHA-1( pw_salt + "\x00" + uid + "\x00" + パスワード )

- `account.pw_salt` は `default.yaml` の設定項目で、空なら Wiki名です。塩は秘密ではなく、
  別のWikiで同じID・同じパスワードでも値が違うようにするためのものです
- IDが混ざるので、同じパスワードの人でもハッシュ値が違います
- `\x00` は入力できない文字で、`("a", "bc")` と `("ab", "c")` を区別するための区切りです
- 作りかたを知っているのは `wikilib.userdb.hash_password(wiki_dir, uid, raw)` だけです

#### 塩を変えると、全員のパスワードが通らなくなります

生のパスワードを持っていないので、作り直せません。

| 場面 | どうなるか |
|---|---|
| Wiki名を変える | 塩が Wiki名のままだと全員が通らなくなるので、移す前に旧名を `account.pw_salt` へ書いて固定します（`farmrename.pin_pw_salt`。書けなければ名前を変えない。すでに塩があれば書き換えない） |
| IDを変える | そのアカウントだけ通らなくなるので、`update_user` はパスワードの付け直しを求めます（新しいハッシュは `/.pwhash` で作れる） |
| `pw_salt` を書き換える | 全員が通らなくなります。設定画面では、警告と「理解して編集」のチェックを入れたときだけ編集できます |

#### 旧い形のハッシュは通しません

**旧い形のハッシュは照合せず、移行の仕組みも持ちません**（Wiki設計者の指示、2026-09-21）。
旧い形は、`パスワード + "wiki"` の SHA-1 と、区切りなしの `塩 + uid + パスワード` の SHA-1 です。

- 旧い形のアカウントは、管理者が付け直すと入れるようになります（管理者自身は
  [`./wiki.py resetpw`](/Tech/Accounts/AccountList#管理者が入れなくなったとき)、ほかは `/.admin/accounts` で `/.pwhash` の値を入れる）
- すでにログインしている人のcookieは、付け直すまで効き続けます

#note(type=warn){{
**この持ちかたは、パスワードを守る目的には弱いものです。** Wiki設計者の判断で、
承知のうえでこの形を採っています。

- SHA-1 は速く、総当たりが安く済みます。塩とIDが混ざるので表1枚で全員を一度に解くことは
  できませんが、1人ずつなら安く済みます
- **一覧の画面にハッシュ値を出します**（Wiki設計者の指示）。その画面に届く人には総当たりの
  材料が渡るので、あの画面は管理者だけに絞ってあります
- HTTPSにするかどうかはこの実装の外です。素のHTTPなら、パスワードも合言葉も経路上で読めます
}}

守りを強くするなら、意図的に遅い関数（`hashlib.pbkdf2_hmac` / `scrypt` など）へ移します。
差し替えは `hash_password()` の1か所で済みます。一覧の画面を開いてよいかは
`wikilib.accounts.render_accounts()` の先頭（`sysui.require(..., auth.ADMIN_ONLY)`）で見ています。
