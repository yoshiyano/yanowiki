# ブロックプラグインの丸括弧の対応を数える（不具合修正の要望）

wikiPlugin から wikiSystem 本体（`_sys/wikilib/plugins.py`）への実装依頼です。
**2026-08-25に、本体・wikiPlugin の両方で対応済みです**。
1行の `#name(args){中身}` の中身に丸括弧を含めても、そのまま動きます。

## 現象

1行の `#name(args){中身}` で、中身に `[文字](リンク先)` のような丸括弧を含めると
「本体（{…}）の書きかたが正しくありません」になっていました。`img` などで
「複数行の `{{ … }}` を使う」という回避策を案内していましたが、意図した制約ではなく
正規表現の不具合でした。

## 原因

ブロック呼び出しの1行を読む正規表現が、引数を貪欲マッチ `(.*)` で取っていました。

```python
PLUGIN_BLOCK_RE = re.compile(r'^#([A-Za-z_][\w\-]*)\((.*)\)(.*)$')
```

行内に丸括弧が複数あると最後の `)` まで引数として飲み込み、続く `{…}` を取り出せません。

インラインの `PLUGIN_INLINE_RE` は `[^()]*` で丸括弧を明示的に除いており、こちらは
「インラインの引数には丸括弧を書けない」という意図した制約です。

## 修正

正規表現の代わりに、丸括弧の対応を数える走査（`_match_plugin_block`）で
`(name, args, tail)` に分けます。

- 開き括弧の直後から1文字ずつ見て、深さが0に戻った `)` で引数を閉じる
- 引用符（`"`・`'`）の中の丸括弧は数えない（`split_plugin_args` と同じ扱い）。
  `#note(label="a(b)c")` も `#note(label="値の中の)閉じ括弧")` も正しく読める
- 閉じ括弧が見つからなければ、プラグイン呼び出しとして扱わない（従来どおり）

`tail` から本体を取り出す処理は丸括弧を見ないので、変えていません。
複数行の `{{ … }}`・引数無し（`#name()`）の呼び出しも、これまでどおり動きます。
