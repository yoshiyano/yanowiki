# 添付ファイルの管理

置き場所はページのパスをそのままミラーします（配信と同じ考えかた）。

| ページ | 添付の置き場所 |
|---|---|
| `wiki/index.md` | `attach/index/` |
| `wiki/Tech/index.md`（`/Tech`） | `attach/Tech/index/` |

対象は `resolve_page_ref()` が決めた `subpath` なので、`/Tech` のような
フォルダ相当のURLでも正しく `attach/Tech/index/` になります。

**ファイルを選んだら、そのまま送ります。**「追加」ボタンは押さなくてよく、スクリプトが
動くときは出しません（動かないときのためにHTMLには残してあり、そのときは押して送ります）。
「同名を置き換える」は、選ぶ前に印を付けておきます。

## クリップボードから貼り付ける

画像は、ファイルを選ばずに**貼り付け**でも追加できます。入口は3つあります。

| 入口 | 使える場面 |
|---|---|
| `Ctrl+V`（添付タブを見ているとき） | PC。どの接続でも使えます。貼れないときは[下記](#貼り付けられないとき) |
| 「クリップ貼付」ボタン | `navigator.clipboard.read()` が使えるとき＝**https か localhost** のみ |
| **「クリップボードからペースト」の枠** | スマートフォン。どの接続でも使えます |

3つ目の枠は、**スマートフォンのための押せる的**です（Wiki設計者の指示、2026-09-10）。
iOS・Androidでは**編集できる欄にフォーカスが無いと「ペースト」のメニューが
出ない**ため、`Ctrl+V` に当たる操作がありません。枠を1つ置いて、そこへ
貼ってもらいます。写真アプリで編集した写真を、**ファイルに書き出さずに**
そのまま貼り付けられます。

### 貼られかたが2通りある

同じ「貼り付け」でも、ブラウザによって届きかたが違います。**どちらも拾います。**

1. `clipboardData` に**画像ファイルとして**入ってくる（PC・Android）
2. **枠の中に `<img>` が差し込まれるだけ**（iOS Safari はこちらのことがある）。
   この場合は差し込まれた画像を `fetch` で読み直してファイルに戻します
   （`blob:` も `data:` も読めます）。読み終えたら枠は空にします

どちらの道でも、最後は同じ `applyPastedFiles()` に合流します。ファイル名は
クリップボードから来たものには付いていないので、**サーバー側で `clipNNN`
（連番）を付けます**（下記）。

`Ctrl+V` は、添付タブを見ていれば**画面のどこをクリックしたあとでも**効きます
（受け手は文書全体。添付欄の外の文字の入力欄へ貼るときだけは横取りしません）。

### 貼り付けられないとき

添付タブで貼り付けたのに画像が届かなかったときは、添付欄に
「**クリップボードに画像がありません**（届いた形式: …）」と出ます。
ブラウザが受け取った形式から、何がコピーされていたかが分かります。

| 届いた形式 | コピーされていたもの | 対処 |
|---|---|---|
| （形式が出ない） | 何も無い。コピーしたプログラムが、渡す前に終わっていることが多い | 下の「画面を撮ってすぐ貼るとき」 |
| `text/uri-list`・`text/plain` | ファイルマネージャで**ファイルそのもの**をコピーした（中身ではなく場所だけが届く） | そのファイルを添付欄へドラッグするか、ファイルを選ぶ |
| `text/html` | Webページの画像を**範囲選択して**コピーした（画像のURLだけが届く） | 画像を右クリックして「画像をコピー」でコピーし直す |

#### 画面を撮ってすぐ貼るとき（Linux）

X11 のクリップボードは、コピーしたプログラムが動いている間だけ中身を渡せます。
撮ってすぐ終わる道具は、終わる前に中身をクリップボードマネージャ（Xfce では
`xfsettingsd`）へ預けないと、画像が消えます。

**Ubuntu 22.04（jammy）の `xfce4-screenshooter -c` はこれに当たり、コピーされません。**
jammy の版（1.9.9）には、コピーし終える前に終わってしまう不具合があります
（本家の 1.10.2 で直っています。Ubuntu では 24.04 の 1.10.5 から）。
jammy では、撮った画像を `xclip` に渡して、`xclip` にクリップボードを持たせてください。

```
xfce4-screenshooter -r -o 'xclip -selection clipboard -t image/png -i'
```

`-r` は範囲を選んで撮る指定です（全画面は `-f`、ウィンドウは `-w`）。
Xfce の「設定」→「キーボード」→「アプリケーションショートカット」に登録しておくと、
キー1つで撮って貼れます。`xclip` が無ければ `sudo apt install xclip` で入れます。

## ファイル名の扱い

**bottleの `FileUpload.filename` は使っていません。** ASCII以外の文字を落としてしまい、
日本語のファイル名が壊れるためです。代わりに次の処理を自前で行っています。

1. `os.path.basename()` で最後の要素だけを採る（`../` を含む名前を無害化）
2. 制御文字・パス区切り・Windowsで予約されている記号（`:*?"<>|`）を取り除く
3. 前後の `.` と空白を落とす（`.hidden` のような隠しファイル化を防ぐ）
4. 255文字までに切る

日本語や空白を含む名前はそのまま保ちます。一覧のリンクではURLエンコードします。

## 制限と確認

- 1ファイルあたりの上限は設定 `attach.max_size`（既定20MB）で決まります。
  詳しくは [リファレンス](/Tech/Reference/EditEntry#添付ファイルの大きさの上限) を参照
- 中身が空のファイルは受け付けません
- 同名のファイルは既定で上書きしません。「同名を置き換える」を選んだときだけ置き換えます
- **削除は取り消せないため、ファイル名を見せて確認してから実行します**
- 削除時は、対象が本当にそのページの添付置き場の直下にあるかを確かめます

## 送る前に大きさを見る

**上限を超えるファイルは、送る前に断ります。** 送ってからサーバーに断られるのでは、
超えたぶんだけ回線と時間を無駄にします。大きなファイルほど、長く待たされてから
断られることになり、いちばん困る場合がいちばん損をします。

ブラウザは選ばれた時点で大きさを知っている（`File.size`）ので、その場で見て
「送るぶん」と「大きすぎるぶん」に分けます。上限そのものはサーバーが決めた値を
`data-max-bytes` で受け取るので、設定を変えれば判断も一緒に変わります。

- 大きすぎるものは、**名前と大きさと上限を添えて**その場で知らせます
- 収まるものが混ざっていれば、**そちらだけ送ります**
- 送るものが何も無ければ、通信そのものを行いません
- 大きすぎるファイルが選ばれたままでも、**削除や移動は行えます**
  （「ファイルが選ばれているか」ではなく「送るものがあるか」で判断しています）

**サーバー側の判定はそのまま残してあります。** 画面を通さずに送られてくる場合が
あるので、こちらを外すわけにはいきません。判定は、書き出す前に実際の長さを見て
行います（`Content-Length` は信用しません）。

## 送信中の進み具合

添付の送信は `XMLHttpRequest` で行い、`upload` の `progress` を見て進み具合を出します。

**`fetch` では送信の進み具合を受け取れません。** 大きなファイルほど、何が
起きているのか分からない時間が長くなるため、ここだけは `XMLHttpRequest` を使います。

送り終えてからサーバーの返事が来るまでの間は「受け取り待ち…」と出します。
100%のまま止まって見えるのを避けるためです。

添付は [何回かに分けて送る](/Tech/EditGuide/ChunkedUpload) ので、進み具合は切れ端ごとの
送信量を足し上げて出します。複数選んだ場合も、全部の合計に対する進み具合になります。

## 本文からの参照

一覧の「本文での書きかた」欄には、**そのまま貼れる形を書き出しています。**
画像の拡張子なら `![名前](名前)`、それ以外は `[名前](名前)` です。

`/` を付けない書きかたが「そのページの添付ファイル」を指すという規約
（[共通の書きかた](/Syntax/Common#リンクとファイルの指しかた)）に沿っています。

隣の「コピー」を押すとクリップボードに入ります。**写せない場面があります**
（httpsでない場所から開いた、権限が下りていない等）。そのときは黙って何も
起きないのではなく、昔ながらのやりかたを試し、それも駄目なら書きかたを
選択した状態にして `Ctrl+C` を促します。

書きかたを文字として出しているのは、この「写せない」場面のためでもあります。
ボタンにファイル名だけが並んでいても、**何を書けばよいのかが分かりません。**

## 一覧の見かた

| 列 | 内容 |
|---|---|
| 種別 | 拡張子から判定したアイコンと名前（画像・動画・音声・PDF・文書・表計算・スライド・圧縮・コード・テキスト） |
| ファイル名 | クリックすると別タブで開きます |
| 大きさ | 読みやすい単位に丸めた値 |
| 日時 | 最終更新 |
| 本文での書きかた | クリックすると本文に貼れる形でコピーされます |

**画面が狭いときは、右の欄から順に落とします**（Wiki設計者の指示、2026-09-06）。

| 画面の幅 | 落とす欄 |
|---|---|
| `85rem`（1360px）以下 | 本文での書きかた |
| `71rem`（1136px）以下 | ＋ 種別 |
| `66rem`（1056px）以下 | ＋ 大きさ |
| `44rem`（704px）以下 | ＋ 日時 |

**ファイル名と操作は常に残します。** どれを触るか選べなくなるためです。

区切りの幅は、その欄を落とさないと表が入れ物に収まらなくなる点から決めました
（測った必要幅は 種別84 / ファイル名113 / 大きさ170 / 日時134 / 書きかた221 /
操作306 px）。広い画面では左のページ一覧が場所を取るので、画面の幅から
`20rem` ほど引いたぶんが表に使える幅になります。

見出し（`th`）と中身（`td`）は別の行にあるので、同じ `attach-col-*` を両方に
付けてあります。1つの指定で1列まるごと落とせます。

なお**幅が `420px` を切ると、残った2列でも収まりません**（ファイル名と操作で
最低419px、うち306pxが操作の3つのボタン）。ここから先は表が横にスクロールします。
落とせる欄がもう無いので、これ以上詰めるならボタンの並べかたに手を入れることに
なります。

**1件ぶんの高さは詰めてあります**（Wiki設計者の指示、2026-09-06。それまでの70%が目安）。
9件で400px取っていたのを280pxほどにしました。**一度に見える件数を増やす**ための
もので、字の大きさ（ファイル名の読みやすさ）は変えていません。縮めたのは上下の
余白と、操作ボタンの丈です。

アイコンは1つのSVGに `<symbol>` としてまとめ、各行からは `<use>` で参照しています
（行ごとにSVGを書き出すと、一覧が長くなるほど無駄が増えるため）。
線は `currentColor` なので、テーマの文字色にそのまま馴染みます。

**画像にマウスを乗せるとサムネイルが出ます。** 実物を縮小して見せるだけなので、
サーバー側でサムネイルを作る必要はありません。ただし読み込みは
「最初にマウスを乗せたとき」まで遅らせています。表の外（`body` 直下）に置くので、
表のスクロールや `overflow` で切られません。

## ドラッグ&ドロップ

**追加の欄にファイルを落としても添付できます。複数まとめて落とせます。**

落とされたファイルはいったん `<input type="file">` に移してから送るので、
そこから先はファイルを選んで追加したときとまったく同じ経路を通ります。
サーバー側にドロップ専用の処理はありません。

## 別のページへ移す

各行の「移動」から、**ページ選択ダイアログ**で移動先を選べます。
書いているうちに「この画像は別のページに置くべきだった」となることがあるためです。

- 移動先は**ページパス**で受け取り、実体の置き場所は `resolve_page_ref()` に決めさせます。
  `/Tech` のようなフォルダ相当のページでも `attach/Tech/index/` に正しく移ります
- **まだ無いページも選べます**（先に添付だけ置いておける）。その場合は
  「移動先のページはまだありません」と添えます
- 移動先に同名があるときは、既定では移しません。「同名を置き換える」を選んだときだけ置き換えます
- 移動は `os.replace()` なので、同じディスク内では中身の複製が起きません
